# 수집 순서와 자동 연결의 수렴

기존 연결기는 먼저 들어온 신호로 기회를 요약하고 그 요약을 다음 신호의 후보로
사용했다. 같은 이름이 여러 부서에 쓰였다는 사실이나 비슷한 경쟁 후보가 나중에
드러나도 앞선 자동 연결은 다시 검토하지 않았다. 보관된 성남 2,404개 신호 중
연결 가능한 2,399개를 비교했을 때 예산서 우선은 6개, 역순은 89개의 소속이 달랐다.

## 완료 경계

`link_signals`는 임시 연결과 기관별 dirty generation을 같은 트랜잭션에 저장한다.
`reconcile_links`는 **이미 연결된** 해당 기관의 자동 신호를 관측일과 원천·내용 키로
정렬해 전체 분할을 다시 계산한다. 생성된 DB ID와 ID가 섞인 기존 dedupe key는
정렬 기준에 쓰지 않는다. 추출·다운로드·LLM 호출은 하지 않는다.

수렴은 재조정 작업의 커밋 시점에 보장된다. 입력이 계속 들어오는 동안의 임시 연결이
즉시 같다는 뜻은 아니다. 같은 입력·설정·보호된 판단이 주어지면 완료 후 자동 분할과
요약은 같아진다. `pipeline run`, 데모 파이프라인, `link replay`도 동일한 완료 단계를
실행한다. replay는 도착 순서에 따라 실제 연결을 수행한 후 이 단계를 실행하며,
입력 파일을 먼저 정렬해 순서 차이를 감추지 않는다.

## 복구와 이력

- DB의 `generation > reconciled_generation`은 재조정 대기다. 매분 sweep과 작업
  재시도가 큐 등록 전후의 중단을 복구한다.
- `reconciled_generation > recommendations_generation`은 추천 작업 등록 대기다.
  기관·세대·조직별 작업 ID와 DB 확인 표시로 부분 등록을 재시도한다.
- 재조정 대기 기관의 기회는 새 추천 후보와 알림 생성에서 제외한다.
- 사람이 검토한 현재·과거 연결, 수동 연결, 관계의 양 끝과 이력 근거는 통째로
  보호한다. 새 자동 신호도 이러한 판단에 임의로 끼워 넣지 않는다.
- 고객 피드백·알림·브리프는 최초 근거 신호와 기회 ID를 고정한다. 이후 발주계획과
  입찰 같은 **새 자동 근거는 계속 연결**하며, 이 추가분은 매번 정규 순서로 다시
  평가한다. 알림 이후 사업 추적을 멈추거나, 새 자동 근거를 다음 재조정의 고정
  근거로 오인하지 않는다. 첫 근거가 삭제·거절됐으면 자동 대체하지 않고 보호한다.
  기존 알림만 남은 이전 데이터도 최초 재조정 또는 추가 연결 전에 같은 기준을 저장한다.
- 동일한 묶음은 기존 기회 ID를 유지한다. 분할·병합은 기존 근거의 겹침으로 ID를
  배정하며, 사라진 묶음의 ID는 삭제하지 않고 주장·금액·확률을 비운 dormant 상태로
  남긴다. 바뀐 연결의 이전·이후 메타데이터는 `link_reconciliation_events`에 보존한다.
- 계획 계산 뒤 짧은 유지보수 잠금을 잡고 입력과 보호 상태를 다시 확인한다.
  달라졌으면 부분 적용 없이 실패하고 새 스냅샷에서 재시도한다.
- 검토·피드백·브리프·알림 발행과 자동 연결은 같은 기회 행 잠금을 사용한다.
  재조정은 진행 중인 사용자 작업이 있으면 즉시 재시도하며, 브리프 생성 중 다른
  자료로 기회가 바뀌지 않는다. 여러 기관을 처리하는 backfill은 기관마다 커밋해
  다음 기관의 계산 중 유지보수 잠금을 잡고 있지 않는다.

## 운영 적용

마이그레이션 `0004`는 기존 연결 기관을 재조정 대기로 등록한다. API·worker를 같은
코드로 배포하고 `manage db upgrade`를 실행해야 한다. 연결된 운영 환경에서 다음
명령으로 수동 완료할 수도 있다.

```bash
manage link reconcile --institution-code LG-41130
# 연결 설정/알고리즘 변경 후 깨끗한 세대도 다시 계산할 때
manage link reconcile --institution-code LG-41130 --force
```

명령은 자동 연결과 이력을 쓰며 알림을 직접 보내지 않는다. 보호된 기회 수와 변경
신호 수를 반환한다. 개별 기관 완료가 원자적이며 여러 기관 전체를 한꺼번에 되돌리는
명령은 아니다. snapshot 변경·잠금 충돌은 재시도 대상이다.

## 검증의 의미

분할 일치율은 정확도가 아니다. 모든 도착 순서가 같은 오연결에 도달할 수도 있다.
기존 합성 추출·연결 품질 기준을 유지하고, 별도로 원자료 정답 검토를 해야 한다.
대규모 기관의 전체 후보 비교는 CPU 비용이 들므로 실제 아카이브와 운영 규모 쿼리
벤치 결과를 함께 확인한다. 보호된 사람의 판단을 자동으로 변경해 순서 일치율을
올리지 않는다.

이 저장소의 CI에서 마이그레이션과 재조정을 실행한 사실은 외부 운영 DB에 적용했다는
뜻이 아니다. 실제 운영 적용과 장기·독립 데이터 검증은 별도 증거가 필요하다.
