# 새 실문서 평가와 남은 검증 범위

2026-09-30에 기존 성남 자료·수기 개발 세트와 다른 공식 문서에서 새 표본을 만들고,

## 발견한 결함과 수정 원칙

긴 회의록을 분할하면 두 번째 청크부터 발언자 머리글이 빠지는데, 규칙 추출기가
청크의 발언자 메타데이터를 사용하지 않아 발언을 누락했다. 단일 집행부 발언자임이
명확한 경우에만 문맥을 이어받도록 보완했다. 의원·의장·불명확한 복수 발언자는
집행부로 승격하지 않고, 원문 인용도 고쳐 쓰지 않는다. 이름만 있는 별도 발언자 줄도
검사한다. 독립적인 합성 회귀 사례로 수정 전 실패와 수정 후 통과를 확인했다.

신규 구매 없이 기존 시스템의 유지관리 예산만 통합한 발언이 미래 구매로 노출되는
오류도 별도로 수정했다. 신규 설치·구매·개발·건립 등 구체적인 조달 행위가 없는
유지관리 발언을 제외하고, 신규 자산 구매가 섞인 경우는 유지한다.
규칙 수정 뒤 같은 자료를 다시 재는 것은 **이미 본 자료의 회귀 평가**이며, 또 다른
독립 검증으로 부르지 않는다. 정답·제목 대응 기준을 모델 출력에 맞추지 않는다.

최종 코드 `e72651d0a3f52b786069fbf62193255188f6b651`의 동일 표본 재실행은
**추출 0개, 일치 0/28, 음성 사례 오탐 0/15**였다. 잘못된 유지관리 신호는 제거했지만
새 표본의 재현율은 여전히 0이며, 추출이 없어 정밀도는 `null`이다.
[수정 후 출력 전체](data/holdout-2026-09-30/result-regression.json)를 함께 보존한다.
이는 공개한 실패를 다시 확인한 회귀 결과로, 새로운 블라인드 정확도 측정이 아니다.

비교를 위한 기존 합성 평가와 수기 54건의 수정 전 결과는

## 실행과 해석

```bash
cd apps/api
uv run manage eval holdout ../../docs/data/holdout-2026-09-30/manifest.json \
  --code-revision "$(git rev-parse HEAD)" --out /tmp/fresh-extraction-report.json
```

`--out`은 새 파일이어야 한다. 원본과 기존 결과를 덮어쓰지 않는다. 네트워크·DB·모델
키를 사용하지 않으며 유료 제공자로 자동 전환하지 않는다.

제목 대응은 사전에 정한 원문 구절만 사용한 1:1 최대 매칭이다. 키워드 목록만 같다고
같은 사업으로 채점하지 않는다. 대응이 모호하면 해당 금액·연도 등 필드 채점을 제외하고
제외 건수를 남긴다. 누락된 정답 필드는 채점 불가, 명시적인 `null`은 값 없음 정답이다.
금액 허용 오차는 기존 평가와 같은 2%다. 맞은 신호만의 필드 정확도와 전체 정답 기준
회수율을 함께 출력한다. 제목 구절 평가 역시 사람의 사업 동일성 판정을 대체하지 않는다.

| 장기 실성능이 검증됐는가 | 아니오. 실제 동결 예측과 후속 발주 결과가 함께 쌓인 평가 가능 코호트가 없음 |

다음 정확도 측정은 현재 표본을 보며 개선한 이후 새 기관·새 문서를 다시 고정하고,
원문에 근거한 사람 검토와 함께 해야 한다. 장기 평가는 현재 시점의 예측을 보존한 뒤
실제로 후속 공고를 관측해야 한다. 과거 날짜를 붙이거나 관측되지 않은 공고를 음성으로
세어 이 두 조건을 대신하지 않는다.
