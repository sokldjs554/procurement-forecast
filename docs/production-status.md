## 운영은 아직 미완료

확인한 Render 워크스페이스에는 이 프로젝트의 서비스와 DB가 없다. 이번 작업에서 유료 자원을 생성하거나 기존 타 프로젝트 자원을 변경하지 않았다.

- 구성한 자원은 월 **$55.30**(Render 기본 자원 비용)이며 GCS·트래픽·외부 API·메일·결제 비용 등은 별도다. [비용·필수 설정·배포 순서](render-deployment.md)에 실제 구성과 금액을 적었다.
- GCS 버킷/접근 권한, 원문 수집 키, 실제 메일/결제 설정이 필요하다. 이 값은 Render의 비밀값 입력란에 넣으며 Git/채팅에 기록하지 않는다.
- 연결된 Render 도구에는 worker/Blueprint 생성 기능이 없어 Dashboard 또는 인증된 CLI/API로 프로비저닝해야 한다.
- 배포 후 같은 커밋의 DB 마이그레이션, API/웹/작업자 상태, 인증 흐름, 실제 수집·원문 저장, 재검증 dry-run/apply 결과까지 확인해야 운영 반영 완료다.
- 저장소의 실데이터 신호 아카이브는 전체 원문·원문 근거를 포함하지 않는다. 이를 운영 원문 DB로 간주해 검증을 통과시킬 수 없다.

## 기존 원문 재검증

운영 DB 백업과 쓰기 작업 중지를 확인한 뒤, 같은 날짜·범위로 실행한다. 먼저 반환된 `counts`, `issues`, `examples`, `manual_review_required`를 검토한다.

```sh
manage pipeline revalidate --source clik_minutes --today 2026-09-29 --out audit.json
manage pipeline revalidate --source clik_minutes --today 2026-09-29 \
  --apply --expected-digest '<audit.json의 digest>' --out applied.json
```

`has_more`가 참이면 반환된 `next_after_id`를 다음 실행의 `--after-id`로 사용한다. 각 페이지마다 dry-run을 먼저 실행한다. 데이터·설정·판정이 바뀌면 기존 digest 적용은 거절된다. 테이블 쓰기 잠금은 최대 5초 대기 후 실패하므로 유지보수 시간에 실행한다. 이 명령은 새로운 알림을 보내거나 유료 모델을 호출하지 않는다.

사람이 검토한 문서의 원문이 바뀌면 수집도 명시적으로 실패한다. 현재 정책은 그 수집 트랜잭션 전체를 롤백해 기존 원문과 검토를 보호하는 것이다. 운영자는 변경 원문과 기존 판정을 비교하고 명시적인 이행 방법을 정해야 한다. 보호를 끄거나 검토 기록을 삭제해 수집을 강제로 진행하지 않는다.
