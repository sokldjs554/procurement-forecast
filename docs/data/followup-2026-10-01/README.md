## 수정과 재현

발언 전체의 최대 금액을 사업 예산으로 고르던 오류를 재현했다. 조건부·과거 금액을 제외하고 남은 금액이 여러 종류면 임의로 하나를 고르지 않는다. 번호 제목 아래 `재원별 예산액 전년도당초예산액` 순서의 합계표도 제목 경계·표 단위와 함께 읽는다. 실제 문서 분할 경로와 원문 오프셋까지 테스트했다. 기존 정답과 기존 결과는 수정하지 않았다.

- 기존 33사례/20신호: 제목 일치 1 → 4, 출력 6 → 9. 일치한 4건 중 금액 정답 3건, 분류 정답 1건. 음성 사례 오탐은 2/16으로 그대로다. `before-v7.json`, `development-v8.json` 참조. 이미 본 자료의 회귀 결과이며 독립 성능 향상이 아니다.
- 새 고양시 원문 1개, 발췌 4개(정답 2신호, 음성 2개)를 코드 수정 이후 **출력 보기 전에** 고정했다. 동일 구현 에이전트가 작성한 작은 편의 표본으로, 별도 전문가/블라인드 평가라고 부르지 않는다. 정확한 원문·해시·고정 시각은 manifest와 retrieval 기록에 있다.
- 새 표본 v7/v8 모두 제목 일치 1/2, 음성 오탐 0/2. 맞은 방호장비 금액 120만원은 정확하지만 연도는 누락됐고 관용차 신호는 놓쳤다. 일반화 개선은 입증되지 않았다. 이 결과를 본 뒤 정답이나 코드를 추가 튜닝하지 않았다.

## 과거 공고 대조

`historical-followup.json`에 검색 범위·공식 후속 자료·공고 후보·미확인 이유를 남겼다. 세곡동 공사 안내와 일원1동 설치 완료 보도는 확인했으나, 원 입찰공고 및 입력 문서의 당시 공개일은 아직 확인되지 않았다. 신사동·세곡동 두 사업 중 세곡동만 확인한 것을 전체 적중으로 세지 않는다. 현재 채점 가능한 과거 예측은 0건이며 적중률은 null이다. 날짜를 소급하거나 검색 미발견을 음성으로 처리하지 않는다.

이 작업은 추출 결함 일부를 수정하고 추가 평가·과거 대조를 실행한 것이다. 독립 실데이터 정확도 또는 장기 예측 성능을 해결했다는 결과가 아니다.

## 통합 검증에서 발견한 회귀와 v9 보완

v8 CI 코드 `909a470`에서 API 970개와 웹·오케스트레이터·브라우저 E2E·Docker 빌드는 모두 통과했으나, 합성 게이트 외 수기 세트 금액 정확도가 v7 0.889 → v8 0.815로 내려갔다. `eval-all-v8.json` 원본을 남겼다. 이미 예산을 확보하거나 설계만 완료한 것을 과거 지출로 오인했고, 국비와 총액을 모두 미확정 처리한 것이 원인이었다.

v9에서는 `이미`라는 단어만으로 지출 완료를 판정하지 않으며, 명시된 총액이 하나면 재원 구성액과 구분한다. 여러 사업 총액은 여전히 기권한다. 새 합성 재현 테스트에서 먼저 실패를 확인하고 수정했다. DB 캐시 없는 동일 제공자+운영 근거 검증기로 수기 54건을 전후 재실행한 결과 제목 P/R 0.931/0.54, 금액 정확도 0.889를 복구했다. 중간 실패 결과도 별도 파일로 보존했다. 최종 v9 전체 CI는 별도로 확인한다.

고양시 자료는 v8 출력을 이미 보았으므로 `goyang-regression-v9.json`은 새 독립 평가가 아니다. 두 실문서 세트의 v9 결과도 여전히 정확도 해결을 입증하지 못했다.
