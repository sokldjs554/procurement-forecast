# 데이터 품질 보완 기능 사용

공개 데모 배포와 별개로 실제 API/작업자 환경에서 사용하는 기능이다. 아래 명령은 수집이나 유료 LLM을 호출하지 않는다. 수정된 코드를 실행하기 전에 같은 리비전의 `manage db upgrade`가 필요하다.

## 사업 하나와 여러 계약

관리자로 `/admin/relations`를 연다. 사업 기회와 계약 기회를 선택하고 양쪽 원문 근거를 확인한 뒤 신호를 선택한다. 후보는 `proposed`, 사람이 근거를 대조해 확인한 관계는 `confirmed`, 관계를 철회하면 `rejected`다. 사업 하나에 여러 계약을 연결할 수 있지만 계약 하나를 여러 사업에 동시에 확정할 수는 없다.

관계는 신호 소속을 바꾸거나 계약 금액을 사업 예산에 더하지 않는다. 같은 기관, 사업 측의 회의록/예산 근거, 계약 측의 조달 근거, 원문에 실제로 존재하는 인용을 검사한다. 순환 관계를 허용하지 않는다. 기존 혼합 기회 감사 목록은 자동 분해 명령이 아니다. 올바른 분해는 원문과 기존 검토·추천 이력을 대조한 별도 이행이 필요하다.

관리자 판정은 `expected_version`과 `Idempotency-Key`를 사용한다. 응답을 받지 못하면 같은 키로 재시도한다. 409 충돌이면 최신 상태를 불러와 다시 판단한다. 근거가 수정되거나 거절되면 저장된 확정 이력은 보존하면서 화면에는 `stale`(재검토 필요)로 표시한다. 일반 사용자에게는 운영자 메모와 판정자 이력을 공개하지 않는다.

`0003` 마이그레이션은 관계와 판정 이력만 추가한다. 자동 downgrade는 이력을 삭제하므로 거절한다. 이행을 되돌려야 하면 먼저 관계/이력을 보존하는 별도 계획을 마련한다.

## 기관별 수집·원문 현황

```sh
manage sources coverage --out coverage.json
manage sources coverage --no-verify-raw --out coverage-metadata.json
```

설정된 대상과 실제 문서를 받은 기관은 다르다. 보고서는 fixture를 제외하고 문서 수, 원문 참조, 원문 가용/누락/미검증, 공개일 근거, 수집원 최근 결과를 분리한다. 로컬 원문은 파일이 읽히는지 확인할 뿐 해시 무결성을 보장하지 않는다. 원격 저장소 참조는 외부 호출 없이 미검증으로 남긴다. 전역 API 접근 설정은 전국 수집 성공 증거가 아니다.

CLIK 수집은 해당 회의의 기존 DOCID 집합과 현재 목록을 비교해 새 판을 받는다. 저장된 판 정보를 조회하는 수집 경로에서는 요청 종료일 기준 기본 30일 전까지 목록을 다시 확인한다(`sources.config.overrides.revision_lookback_days`, 0이면 확장 없음). 요청 시작일이 더 이르면 그 명시적 backfill 범위를 유지한다. 요청 기간 밖의 확장 구간에서는 이미 저장된 회의만 새 DOCID를 받을 수 있고, 아직 저장하지 않은 오래된 회의는 가져오지 않는다. 따라서 늦게 처음 게시된 회의의 누락까지 이 기능으로 해결하지는 않는다. 목록·상세 호출은 기존 공유 일일 한도와 `max_details`를 따른다.

DOCID 목록 순서를 확정본/최신 수정 시각으로 해석하지 않는다. 역조회 기간보다 오래된 회의의 수정판이나 아직 받지 않은 과거 회의를 조사할 때는 `manage sources ingest`의 기간에 그 회의일을 포함한다. 사람 검토나 관계 판정이 있는 원문을 바꾸려 하면 트랜잭션을 거절해 보존한다.

## 사람 검토를 평가자료로 보관

```sh
manage eval export-reviews --source clik_minutes --limit 500 --out reviews.jsonl
```

첫 줄은 manifest, 나머지는 근거가 확인된 사람 판정이다. 정정한 필드만 `reviewed_fields`에 들어가며 단순 승인으로 분류 등 모든 필드를 정답으로 선언하지 않는다. 원문/인용/오프셋이 없거나 긍정 판정의 사실 근거가 충돌하면 제외 사유를 집계한다. 낮은 기계 확신도만 있는 사례는 사람 승인으로 포함할 수 있지만 기계 경고는 지우지 않는다.

문서·원문 해시·파싱된 텍스트가 같은 연결군은 같은 train/validation/test 분할에 둔다. 분할은 해당 동결 export 범위의 분할이다. 서로 다른 시점에 만든 export를 임의로 합치면 다시 문서 중복을 검사해야 한다. `has_more`가 참이면 제한된 표본이며, 범위/한도를 조정해 새 완전한 평가 버전을 만든다. 파일은 임시 파일에서 완성한 뒤 교체한다.

## 지금 관측한 입력과 예측 동결

```sh
manage eval freeze --institution-code LG-41130 \
  --code-revision '<실제로 실행 중인 커밋 SHA>' --out forecast-now.jsonl
```

새 DB 세션의 REPEATABLE READ READ ONLY 거래에서 현재 원문 텍스트·신호·벡터·연결·예측·관련 설정을 보관한다. 과거 날짜를 입력해 당시 상태처럼 만드는 옵션은 없다. 코드 리비전은 운영자가 제공한 값이라는 표시를 남긴다. 원문 바이너리, OCR 엔진 입력 전체, 제공자 모델 가중치/LLM 원호출은 포함하지 않으므로 완전한 파서/모델 재실행 아카이브가 아니다. 누락 입력은 불완전 사유에 표시한다. 신호 제한을 넘으면 부분 파일로 기존 파일을 덮어쓰지 않는다.

이 스냅샷을 실제 관측 시점마다 보관하고 이후 공고 결과를 대조해야 전향적 예측 평가가 가능하다. 명령을 추가한 것만으로 과거/장기 예측 성능을 측정한 것은 아니다.

## 연결 순서 감사

`manage link replay`는 **빈 별도 DB**에서 수행한다. 비교마다 새 DB를 만든다. 롤백만으로 같은 DB를 재사용하면 테이블/인덱스 상태와 통계가 남아 시간 비교가 왜곡된다.

```sh
manage link replay docs/data/seongnam-link-signals.jsonl.gz --today 2026-09-29 --out publication.json
manage link replay docs/data/seongnam-link-signals.jsonl.gz --first budget_book --today 2026-09-29 --out budget-first.json
manage link replay docs/data/seongnam-link-signals.jsonl.gz --order reverse --today 2026-09-29 --out reverse.json
```

세 명령은 각각 새 DB를 사용해야 한다. API 디렉터리에서 실행하면 입력 경로는 `../../docs/data/...`다. 서로 다른 결과가 나오면 원문을 대조할 민감 사례이며, 같은 결과가 나온다고 연결 정확도를 입증하지는 않는다. 보존 아카이브에는 전체 원문이 없으므로 해당 결과를 역사적 원문 재검증으로 표현하지 않는다.
