2026-09-29, [PR #49](https://github.com/sokldjs554/procurement-forecast/pull/49).

## 고친 문제

| 기존 한계 | 이번 변경 | 보장하지 않는 것 |
|---|---|---|
| 인용이 원문에 있으면 의원 요구도 집행부 계획으로 승인 | 회의록 전체의 발언 경계와 청크 오프셋으로 인용의 발언자를 확인. 의원·위원장·미상 발언, 짧은 동의만 있으면 검토 대기 | 답변이 해당 사업의 약속인지, 부정·조건·제3자 인용인지까지 의미적으로 검증하지 않음 |

| 미래 공고·현재 기회 요약을 과거 평가에 사용 | 기준일까지 공개된 승인 신호와 확정 연결만 사용 | 현재 연결 그룹 자체가 나중 자료의 영향을 받았을 수 있음 |
| 최근 성공은 포함하고 최근 미성공은 제외 | 성공 여부와 무관하게 동일한 540일 관측기간을 채운 최초 신호만 전환율 분모에 포함 | 공고 미수집과 실제 미발주를 구분하지 못함 |
| 나중의 강한 발언으로 최초 발언 강도를 바꿈 | 최초 신호의 강도로 코호트 고정 | 표본이 작으면 전환율은 불안정함 |
| 회의일·회계연도 추정일을 공개일처럼 계산 | 문서 공개일과 신호 관측일 중 늦은 날 사용. `meeting_date`·`fiscal_year`·`last_modified`·`crawled` 추정 출처 제외 | 실제 게시일이 없는 자료로 선행 기간을 증명할 수 없음 |

백테스트의 방법 버전은 `public-date-cohort-v2`입니다. 이전 버전으로 저장된 평가 결과는 추천 확률 보정에 재사용하지 않습니다. 이 결과의 이름은 **현재 연결의 회고적 진단**이며, 당시 시스템이 실제로 미리 찾아냈음을 증명하는 예측 재현이 아닙니다.

## 재현 방법

`Integrity audit` CI는 PR의 기준 커밋과 변경 커밋을 별도 DB에서 실행합니다.

1. 동일한 합성 세계: 시드 7, 기준일 2026-09-25, 규모 1.0.
2. 각 코드의 `manage demo run` → `manage eval all`; 기존 추출·연결 P/R 0.95 게이트 유지.
3. 저장된 실제 신호 `docs/data/seongnam-link-signals.jsonl.gz` 2,404건을 각각 두 번 연결. 반복 결과의 신호 키 그룹이 동일한지 확인.
4. `make bench`로 공고 10만·신호 40만·문서 15만·청크 60만·추천 30만 건의 실행 계획 측정.
5. 원본 JSON·연결 그룹·리포트를 `integrity-audit` 아티팩트로 보관.

실제 신호 replay는 추출을 다시 실행하지 않습니다. 저장된 Claude 응답 449개에도 원문 전체가 없으므로 이번 발언자 검증의 실문서 정밀도/재현율을 측정했다고 주장하지 않습니다. 유료 LLM 호출은 실행하지 않았습니다.

## 기존 데이터에 적용할 때

- 코드 배포만으로 기존 신호의 판정과 기존 연결은 바뀌지 않습니다. 현재 DB를 백업하고 원문·문서 버전·응답 캐시를 보존한 복제 환경에서 다시 추출/검증하고 새 연결을 만들어 비교해야 합니다.
- `process_document`는 해당 문서에서 파생된 신호를 교체합니다. 운영 DB에 무작정 반복 실행하지 말고, 연결 및 추천까지 복제 환경에서 함께 재생성한 결과를 검토해야 합니다.
- 이번 변경 후 모호한 신호는 별도 기회로 남습니다. 같은 사업이 둘로 나뉠 수 있으므로, 잘못 합친 비율과 놓친 연결 비율을 함께 측정해야 합니다.
- CLIK의 기존 문서 중 `council_id`가 있고 공개일 출처가 없던 자료도 선행 기간에서 제외합니다. 실제 게시 시각이 확인되면 그 출처를 기록한 뒤 다시 평가합니다.

## 남은 한계를 보완하는 순서

1. **원문 정답 세트 확보:** 질의·답변 전체, 발언자, 사업명, 금액, 부정·조건부 표현, 공개일 출처를 보존합니다. 자동 승인과 검토 대기를 따로 집계하고, 규칙을 맞추는 세트와 마지막 평가 세트를 분리합니다.
2. **연결 정답과 관계 분리:** 사업이 같은지, 하나의 예산 사업에서 나뉜 계약인지, 위치·연차가 다른 사업인지를 구분해 라벨링합니다. 예산사업 1개–조달계약 N개의 관계를 강제로 동일 기회로 합치지 않는 모델이 필요합니다.
3. **후보 검색부터 측정:** 정답 연결이 상위 12개 안에 들어오는 비율을 먼저 잽니다. 기관·부서·위치·사업명 후보를 보충한 뒤 연결 정밀도, 재현율, 보류 비율을 함께 비교합니다. 사업명만 다른 예산 행을 강제 병합하는 규칙으로 재현율을 높이지 않습니다.
4. **2~3년 수집 범위와 진짜 시점 재현:** 실제 게시일과 시스템 최초 수집일을 분리하고, 과거 기준일마다 그때 이용 가능했던 문서만 추출·연결·추천합니다. 각 기준일로부터 540일간 추적한 뒤 그 기간 안에 나온 공고를 결과로 비교하고 지역·연도별 성능과 표본 수를 제시합니다.
5. **검토 결과를 피드백으로 사용:** 잘못된 승인·연결을 수정하고 기존 기회 및 추천까지 다시 계산할 수 있는 검토 흐름이 필요합니다. 자동 승인 확대는 별도 평가 세트에서 오류 감소를 확인한 뒤 진행합니다.

공개 데모 구현과 실제 예측 성능 검증은 별개의 작업입니다. 포트폴리오에는 합성 동작 검증, 수기 정답 평가, 실문서 측정을 각각 표시해야 합니다.
