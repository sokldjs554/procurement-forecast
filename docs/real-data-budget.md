# 지방재정365 예산서 첫 실호출 (2026-09-27)

조달청 소스는 30일치를 실제로 적재해 확인했습니다([`real-data-run.md`](real-data-run.md)). 이번에는 같은 방식으로 예산서 소스(`lofin_budget`, `sources/lofin.py`)를 처음으로 실제 API에 붙여 보려 했습니다. 결론부터 말씀드리면 **API에 한 번도 닿지 못했습니다.** 그래서 API 모양, 목록 건수, 파일 호스트, 추출 정확도 가운데 실제로 잰 것은 없습니다. 이 문서에는 무엇을 호출했고 어디서 막혔는지, 그리고 네트워크 없이 할 수 있었던 어댑터 수정을 적습니다. 숫자는 모두 이 세션에서 직접 본 것입니다.

- 키: 이날 발급된 `APP_LOFIN_API_KEY`. 키는 환경 변수로만 넘겼고 출력·파일·커밋에 남기지 않았습니다.
- 환경: 개발 컨테이너. 외부 요청은 컨테이너의 에이전트 프록시를 거칩니다.
- `APP_ANTHROPIC_API_KEY`는 설정돼 있지 않았습니다. 예산서까지 갔다면 규칙 기반 추출기로 돌았을 것입니다. 실제로는 거기까지 가지 못해 LLM 비용은 0입니다.

## 요약

- 어댑터 기본값(`https://lofin.mois.go.kr/HUB/BGTBOOK`)으로 보낸 목록 호출 3번이 모두 TLS 단계에서 끊겼습니다(`Connection reset by peer`). 요청이 서버에 닿기 전이라 키도 전달되지 않았습니다.
- 새 사이트는 두 이름 모두 막혔습니다.
  - `www.lofin365.go.kr`: 프록시가 연결을 거절했습니다(CONNECT 403). 컨테이너 네트워크 정책이 막은 것입니다.
  - `lofin365.go.kr`: 7번 중 2번 연결됐는데 두 번 다 `301 → https://www.lofin365.go.kr/`였습니다. 나머지 5번은 TLS 단계에서 끊겼습니다.
- 여기까지 본 뒤, 이 세션의 자동 권한 검사가 추가 탐색을 막았습니다. 막힌 것은 `lofin365.go.kr`의 후보 경로에 키를 붙여 보내는 요청과, 키 없이 후보 경로를 두드려 보는 요청입니다. 그래서 OpenAPI 안내 페이지도 읽지 못했습니다. 네트워크 정책을 우회하는 경로(다른 프록시, 미러, 캐시 등)는 시도하지 않았습니다.
- 공공데이터포털 데이터셋 15138708의 안내 페이지(`www.data.go.kr`)도 프록시가 막았습니다(CONNECT 403). 이 데이터셋이 `apis.data.go.kr`에서 호출하는 API인지, 지방재정365로 넘기는 링크형인지 확인하지 못했습니다. `apis.data.go.kr`은 열려 있지만(키 없이 `/`에 400) 서비스 경로를 모르는 상태에서 서비스키를 붙여 추측 호출하지는 않았습니다.
- 네트워크 없이 할 수 있는 수정은 했습니다. 이제 예산서 파일을 받기 **전에** 목록 행을 회계연도·수집 창·기관 목록으로 거릅니다. 전에는 목록에 나온 파일을 모두 내려받은 뒤에야 등록일로 걸렀습니다. 호스트도 설정으로 바꿀 수 있게 했습니다(§3).
- `pytest` 301개 통과(299 → 301). `manage eval all`의 JSON은 main과 값 80개가 모두 같습니다.

## 1. 호출 기록

모든 요청은 `curl`로 보냈고 상태 코드와 크기만 출력했습니다. 키를 붙인 요청은 첫 번째 줄뿐입니다.

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `GET https://lofin.mois.go.kr/HUB/BGTBOOK?Type=json&pIndex=1&pSize=5&fyr=2025` + `Key` | 3 | 3번 모두 `curl: (35) Recv failure: Connection reset by peer` |
| `GET https://lofin.mois.go.kr/` | 7 | 7번 모두 TLS 단계에서 끊김 |
| `GET http://lofin.mois.go.kr/` | 2 | 프록시의 `503`, 본문 "upstream connect error or disconnect/reset before headers … remote connection failure" |
| `GET https://lofin365.go.kr/` | 7 | `301 → https://www.lofin365.go.kr/` 2번, 끊김 5번 |
| `GET https://www.lofin365.go.kr/` | 2 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://www.data.go.kr/` | 1 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://apis.data.go.kr/` | 1 | `400` (게이트웨이 응답, 연결은 정상) |

`lofin.mois.go.kr`은 HTTP로도 HTTPS로도 연결되지 않았습니다. `lofin365.go.kr`은 가끔 연결되지만 곧바로 막힌 `www`로 보냅니다. 두 호스트가 한 번씩이라도 응답한 것으로 보아 호스트 자체는 살아 있습니다. 끊김이 제공처 방화벽 때문인지 컨테이너 경로 문제인지는 여기서 구분할 수 없었습니다. 조달청 적재 때도 해외 경로에서 TLS가 가끔 끊겼지만, 그때는 12번 중 7번이 연결됐습니다.

### 확인하지 못한 것

과제로 받았던 측정 가운데 이번에 한 것은 없습니다.

| 항목 | 상태 |
|---|---|
| 요청 URL 모양, 파라미터, 응답 봉투, 필드명 | 확인 못 함. 어댑터는 여전히 명세 기준 추정값 |
| 오류 형식(잘못된 키, 빠진 파라미터), 페이지 이동 방식 | 확인 못 함 |
| 회계연도별 행 수(2024~2026), 243개 지자체 중 몇 곳, 본예산·추경 비율, 필드 채움 | 측정 못 함 |
| 파일 링크 호스트 분포, 파일 형식 | 측정 못 함 |
| 예산서 표본 10권 적재·처리, 예산 사업 20건 수기 대조 | 못 함 |

실제 행을 본 적이 없어서, `tests/unit/test_sources.py`의 새 테스트는 "실데이터 모양" 픽스처가 아니라 명세 기준 계약 테스트라고 적어 두었습니다. 실제 행을 지어내 넣지는 않았습니다.

## 2. 전체 실행에 필요한 것

1. **네트워크 허용**
   - `www.lofin365.go.kr`: 지금은 프록시가 막습니다. `lofin365.go.kr`이 여기로 보내므로 API가 옮겨 갔다면 거의 확실히 필요합니다.
   - `lofin.mois.go.kr`: 허용 목록에는 있지만 TLS 연결이 끊깁니다. 이 경로를 쓰려면 컨테이너 밖(국내 망)에서 한 번 연결되는지부터 확인해야 합니다.
   - `www.data.go.kr`: 데이터셋 15138708의 안내와 명세를 읽을 때만 필요합니다.
2. **파일 호스트**: 목록을 한 번도 받지 못해 **어느 호스트를 열어야 하는지 아직 모릅니다.** 목록 응답의 링크가 `www.lofin365.go.kr` 한 곳이면 1번으로 충분합니다. 지자체 누리집으로 흩어져 있으면 호스트마다 허용해야 합니다. 목록만 받아 보면 바로 알 수 있습니다. 파일 호스트가 막혀 있어도 목록 행 수와 필드는 잴 수 있고, 그때 파일 호스트 목록과 건수를 이 문서에 채우면 됩니다.
3. **이 세션의 권한**: 키를 붙인 후보 경로 호출과 키 없는 경로 탐색이 세션의 자동 권한 검사에 막혔습니다. 다음 실행에서 탐색까지 맡기려면 이 호출들을 허용해 주셔야 합니다.

네트워크가 열리면 순서는 이렇습니다.

```bash
cd apps/api
# 1) 목록만: 기관 목록을 비워 두지 말고, 몇 곳으로 좁혀서 파일 다운로드를 제한합니다
psql "$DB" -c "UPDATE sources SET config = config || '{\"institutions\": [\"서울특별시 강남구\"]}' WHERE key = 'lofin_budget'"
uv run manage sources ingest -s lofin_budget --days 365 --max-calls 30 --report budget.json
# 2) 적재된 예산서 처리
uv run manage pipeline run
```

`budget.json`의 `books`에 목록 행 수(`listed`), 거른 이유별 건수(`skipped:*`), 내려받은 권수(`downloaded`)가 나옵니다. 호스트나 경로가 다르면 코드 수정 없이 설정으로 바꿉니다.

```sql
UPDATE sources SET config = config || '{"base_url": "https://www.lofin365.go.kr",
  "overrides": {"list_path": "/새/경로", "url_fields": ["실제_필드명"]}}'
WHERE key = 'lofin_budget';
```

## 3. 고친 것: 내려받기 전에 거르기

예산서 한 권은 수십~수백 MB이고, 목록에는 지자체마다 본예산과 추경이 해마다 올라옵니다(243개 지자체 × 여러 권). 그런데 어댑터는 목록 행마다 곧바로 파일을 내려받았고, 수집 창(등록일) 확인은 **받은 뒤에** 했습니다. 창 밖의 권도 모두 내려받고 버리는 구조였습니다.

이제 행마다 이 순서로 판단하고, 통과한 행만 내려받습니다.

| 순서 | 거르는 조건 | 이유 |
|---|---|---|
| 1 | 기관명이나 파일 URL이 없음 (`skipped:unmapped`) | 매핑 실패. 필드명이 다르면 여기 쌓임 |
| 2 | 행의 회계연도가 요청한 연도 범위 밖 (`skipped:fiscal_year`) | 목록이 `fyr` 파라미터를 무시하는 경우에 대비 |
| 3 | 등록일이 수집 창 밖 (`skipped:window`) | 전에는 다운로드 뒤에 하던 확인 |
| 4 | `sources.config`의 `institutions`에 없는 기관 (`skipped:institution`) | 목록이 없으면 이 단계는 건너뜀 |

- 요청하는 연도 범위는 전과 같이 수집 창 첫해부터 마지막 해 + 1년입니다. 다음 해 본예산은 12월에 올라오기 때문입니다.
- `institutions`는 띄어쓰기를 무시하고 비교합니다. 행의 기관명만으로도, 지역명을 앞에 붙인 이름으로도 맞춥니다. 그래서 `"서울특별시 강남구"`는 지역명 "서울특별시", 기관명 "강남구"인 행과 맞고, 같은 목록에 부산광역시 중구가 있어도 `"서울특별시중구"`와 헷갈리지 않습니다.
- 지역명 필드(`region_fields`)는 새로 읽습니다. 실제 목록이 지역명·자치단체명을 따로 준다는 명세에 따른 것이고, 필드명은 다른 필드처럼 추정값입니다. 지역명은 문서의 `sido_hint`로 넘겨 "중구" 같은 동명 기관 해석에 씁니다.
- API 호스트(`base_url`)를 설정으로 바꿀 수 있게 했습니다. 전에는 `list_path`와 필드명만 바꿀 수 있었고 호스트는 코드에 고정돼 있었습니다.
- 코드: `sources/lofin.py`, `sources/registry.py`, `pipeline/backfill.py`(보고서에 `books` 추가). 테스트: `tests/unit/test_sources.py`의 `test_lofin_*` 두 개.

## 4. 남은 일

- 네트워크가 열리면 §1의 "확인하지 못한 것"을 모두 잽니다. 목록 호출은 몇십 번이면 충분합니다(연도 3개 × 페이지 수).
- 실제 응답 한 행을 받으면 이름·URL은 두고 개인정보만 뺀 픽스처로 계약 테스트를 바꿉니다.
- 같은 URL을 두 행이 가리키거나(본예산 파일이 추경 행에 다시 걸리는 경우 등) 파일이 바뀌지 않았으면 다시 받지 않도록 하는 것은, 실제 목록을 본 뒤 필요한지 판단합니다. 지금도 같은 파일은 저장소에서 한 번만 저장·처리됩니다.
- 회의록(CLIK)은 키가 아직 승인되지 않아 이번에 건드리지 않았습니다.
