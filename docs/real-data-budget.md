# 지방재정365 예산서 첫 실호출 (2026-09-27)

조달청 소스는 30일치를 실제로 적재해 확인했습니다([`real-data-run.md`](real-data-run.md)). 이번에는 같은 방식으로 예산서 소스(`lofin_budget`, `sources/lofin.py`)를 실제 API에 붙여 보려 했습니다. 같은 날 두 번 시도했고, 결론부터 말씀드리면 **두 번 모두 API에 닿지 못했습니다.** 두 번째에는 호출할 주소(`www.lofin365.go.kr/lf/hub/BUDLK`)까지 알고 있었지만 개발 컨테이너의 네트워크 정책이 그 호스트를 여전히 막았습니다. 그래서 API 모양, 목록 건수, 파일 호스트, 추출 정확도 가운데 실제로 잰 것은 아직 없습니다. 이 문서에는 무엇을 호출했고 어디서 막혔는지, 그리고 네트워크 없이 할 수 있었던 어댑터 수정을 적습니다. 숫자는 모두 이 세션에서 직접 본 것입니다.

- 키: 이날 발급된 `APP_LOFIN_API_KEY`. 키는 환경 변수로만 넘겼고 출력·파일·커밋에 남기지 않았습니다.
- 환경: 개발 컨테이너(`data-go-kr` 환경). 외부 요청은 컨테이너의 에이전트 프록시를 거칩니다.
- 예산서까지 가지 못해 추출기는 한 번도 돌지 않았고 LLM 비용은 0입니다.

## 요약

- **첫 시도(§1~§4)**: 어댑터 기본값이던 `lofin.mois.go.kr/HUB/BGTBOOK`은 TLS 단계에서 매번 끊겼고, 새 사이트 `www.lofin365.go.kr`은 프록시가 막았습니다(CONNECT 403). 네트워크 없이 할 수 있는 수정으로, 예산서 파일을 받기 **전에** 목록 행을 회계연도·수집 창·기관 목록으로 거르게 했습니다.
- **실제 호출 형식(§5)**: 공개 클라이언트에서 지방재정365 API가 `www.lofin365.go.kr/lf/hub/<데이터코드>` 허브 한 곳이라는 것을 확인하고 어댑터를 거기에 맞췄습니다.
- **BUDLK 호출(§6)**: "우리 지자체 예산서"의 데이터코드가 `BUDLK`라는 것을 포털의 OpenApi 탭에서 확인했습니다. 이 코드로 목록 호출 1번을 보냈지만 `www.lofin365.go.kr`이 **다시 CONNECT 403**으로 막혔습니다. 허용 목록에 넣었다고 들은 뒤 새로 시작한 세션이었는데도 그랬습니다. 요청이 터널을 열기 전에 끊겨 키는 서버에 가지 않았습니다.
- 그래서 응답 봉투, 결과 코드, 필드명, 회계연도별 건수, 지자체 포괄률, 링크 호스트는 **여전히 모릅니다.** 예산서 표본도 한 권도 받지 못했습니다.
- 이번에 바꾼 것은 어댑터의 기본 데이터코드(`api_code`)를 `BUDLK`로 둔 것 하나입니다. 필드명 후보(`DEFAULTS`)는 실제 행을 보지 못해 그대로 두었고, 실데이터 모양 픽스처도 지어내지 않았습니다.
- `pytest` 305개 통과(304 → 305). `manage eval all`의 JSON은 새 DB에서 main과 번갈아 돌려 값 143개가 모두 같습니다.
- **다음 실행에 필요한 것은 하나입니다**: `data-go-kr` 환경의 허용 도메인에 `www.lofin365.go.kr`이 실제로 들어가 있는지 확인해 주세요. 파일 호스트는 목록을 받아 봐야 압니다(§6.4).

## 1. 호출 기록

모든 요청은 `curl`로 보냈고 상태 코드와 크기만 출력했습니다. 키를 붙인 요청은 첫 번째 줄뿐입니다.

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `GET https://lofin.mois.go.kr/HUB/BGTBOOK?Type=json&pIndex=1&pSize=5&fyr=2025` + `Key` | 3 | 3번 모두 `curl: (35) Recv failure: Connection reset by peer` |
| `GET https://lofin.mois.go.kr/` | 7 | 7번 모두 TLS 단계에서 끊김 |
| `GET http://lofin.mois.go.kr/` | 2 | 프록시의 `503`, 본문 "upstream connect error or disconnect/reset before headers … remote connection failure" |
| `GET https://lofin365.go.kr/` | 7 | `301 → https://www.lofin365.go.kr/` 2번, 끊김 5번 |
| `GET https://www.lofin365.go.kr/` | 2 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://www.data.go.kr/` | 1 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://apis.data.go.kr/` | 1 | `400` (게이트웨이 응답, 연결은 정상) |

`lofin.mois.go.kr`은 HTTP로도 HTTPS로도 연결되지 않았습니다. `lofin365.go.kr`은 가끔 연결되지만 곧바로 막힌 `www`로 보냅니다. 두 호스트가 한 번씩이라도 응답한 것으로 보아 호스트 자체는 살아 있습니다. 끊김이 제공처 방화벽 때문인지 컨테이너 경로 문제인지는 여기서 구분할 수 없었습니다. 조달청 적재 때도 해외 경로에서 TLS가 가끔 끊겼지만, 그때는 12번 중 7번이 연결됐습니다.

### 확인하지 못한 것

과제로 받았던 측정 가운데 이번에 한 것은 없습니다.

| 항목 | 상태 |
|---|---|
| 요청 URL 모양, 파라미터, 응답 봉투, 필드명 | 확인 못 함. 어댑터는 여전히 명세 기준 추정값 |
| 오류 형식(잘못된 키, 빠진 파라미터), 페이지 이동 방식 | 확인 못 함 |
| 회계연도별 행 수(2024~2026), 243개 지자체 중 몇 곳, 본예산·추경 비율, 필드 채움 | 측정 못 함 |
| 파일 링크 호스트 분포, 파일 형식 | 측정 못 함 |
| 예산서 표본 10권 적재·처리, 예산 사업 20건 수기 대조 | 못 함 |

실제 행을 본 적이 없어서, `tests/unit/test_sources.py`의 새 테스트는 "실데이터 모양" 픽스처가 아니라 명세 기준 계약 테스트라고 적어 두었습니다. 실제 행을 지어내 넣지는 않았습니다.

## 2. 전체 실행에 필요한 것

1. **네트워크 허용**
   - `www.lofin365.go.kr`: 지금은 프록시가 막습니다. `lofin365.go.kr`이 여기로 보내므로 API가 옮겨 갔다면 거의 확실히 필요합니다.
   - `lofin.mois.go.kr`: 허용 목록에는 있지만 TLS 연결이 끊깁니다. 이 경로를 쓰려면 컨테이너 밖(국내 망)에서 한 번 연결되는지부터 확인해야 합니다.
   - `www.data.go.kr`: 데이터셋 15138708의 안내와 명세를 읽을 때만 필요합니다.
2. **파일 호스트**: 목록을 한 번도 받지 못해 **어느 호스트를 열어야 하는지 아직 모릅니다.** 목록 응답의 링크가 `www.lofin365.go.kr` 한 곳이면 1번으로 충분합니다. 지자체 누리집으로 흩어져 있으면 호스트마다 허용해야 합니다. 목록만 받아 보면 바로 알 수 있습니다. 파일 호스트가 막혀 있어도 목록 행 수와 필드는 잴 수 있고, 그때 파일 호스트 목록과 건수를 이 문서에 채우면 됩니다.
3. **이 세션의 권한**: 키를 붙인 후보 경로 호출과 키 없는 경로 탐색이 세션의 자동 권한 검사에 막혔습니다. 다음 실행에서 탐색까지 맡기려면 이 호출들을 허용해 주셔야 합니다.

네트워크가 열리면 순서는 이렇습니다.

```bash
cd apps/api
# 1) 목록만: 기관 목록을 비워 두지 말고, 몇 곳으로 좁혀서 파일 다운로드를 제한합니다
psql "$DB" -c "UPDATE sources SET config = config || '{\"institutions\": [\"서울특별시 강남구\"]}' WHERE key = 'lofin_budget'"
uv run manage sources ingest -s lofin_budget --days 365 --max-calls 30 --report budget.json
# 2) 적재된 예산서 처리
uv run manage pipeline run
```

`budget.json`의 `books`에 목록 행 수(`listed`), 거른 이유별 건수(`skipped:*`), 내려받은 권수(`downloaded`)가 나옵니다. 호스트나 경로가 다르면 코드 수정 없이 설정으로 바꿉니다.

```sql
UPDATE sources SET config = config || '{"base_url": "https://www.lofin365.go.kr",
  "overrides": {"list_path": "/새/경로", "url_fields": ["실제_필드명"]}}'
WHERE key = 'lofin_budget';
```

## 3. 고친 것: 내려받기 전에 거르기

예산서 한 권은 수십~수백 MB이고, 목록에는 지자체마다 본예산과 추경이 해마다 올라옵니다(243개 지자체 × 여러 권). 그런데 어댑터는 목록 행마다 곧바로 파일을 내려받았고, 수집 창(등록일) 확인은 **받은 뒤에** 했습니다. 창 밖의 권도 모두 내려받고 버리는 구조였습니다.

이제 행마다 이 순서로 판단하고, 통과한 행만 내려받습니다.

| 순서 | 거르는 조건 | 이유 |
|---|---|---|
| 1 | 기관명이나 파일 URL이 없음 (`skipped:unmapped`) | 매핑 실패. 필드명이 다르면 여기 쌓임 |
| 2 | 행의 회계연도가 요청한 연도 범위 밖 (`skipped:fiscal_year`) | 목록이 `fyr` 파라미터를 무시하는 경우에 대비 |
| 3 | 등록일이 수집 창 밖 (`skipped:window`) | 전에는 다운로드 뒤에 하던 확인 |
| 4 | `sources.config`의 `institutions`에 없는 기관 (`skipped:institution`) | 목록이 없으면 이 단계는 건너뜀 |

- 요청하는 연도 범위는 전과 같이 수집 창 첫해부터 마지막 해 + 1년입니다. 다음 해 본예산은 12월에 올라오기 때문입니다.
- `institutions`는 띄어쓰기를 무시하고 비교합니다. 행의 기관명만으로도, 지역명을 앞에 붙인 이름으로도 맞춥니다. 그래서 `"서울특별시 강남구"`는 지역명 "서울특별시", 기관명 "강남구"인 행과 맞고, 같은 목록에 부산광역시 중구가 있어도 `"서울특별시중구"`와 헷갈리지 않습니다.
- 지역명 필드(`region_fields`)는 새로 읽습니다. 실제 목록이 지역명·자치단체명을 따로 준다는 명세에 따른 것이고, 필드명은 다른 필드처럼 추정값입니다. 지역명은 문서의 `sido_hint`로 넘겨 "중구" 같은 동명 기관 해석에 씁니다.
- API 호스트(`base_url`)를 설정으로 바꿀 수 있게 했습니다. 전에는 `list_path`와 필드명만 바꿀 수 있었고 호스트는 코드에 고정돼 있었습니다.
- 코드: `sources/lofin.py`, `sources/registry.py`, `pipeline/backfill.py`(보고서에 `books` 추가). 테스트: `tests/unit/test_sources.py`의 `test_lofin_*` 두 개.

## 4. 남은 일

- 네트워크가 열리면 §1의 "확인하지 못한 것"을 모두 잽니다. 목록 호출은 몇십 번이면 충분합니다(연도 3개 × 페이지 수).
- 실제 응답 한 행을 받으면 이름·URL은 두고 개인정보만 뺀 픽스처로 계약 테스트를 바꿉니다.
- 같은 URL을 두 행이 가리키거나(본예산 파일이 추경 행에 다시 걸리는 경우 등) 파일이 바뀌지 않았으면 다시 받지 않도록 하는 것은, 실제 목록을 본 뒤 필요한지 판단합니다. 지금도 같은 파일은 저장소에서 한 번만 저장·처리됩니다.
- 회의록(CLIK)은 키가 아직 승인되지 않아 이번에 건드리지 않았습니다.

## 5. 실제 API 형식을 찾음 (같은 날 추가)

막힌 뒤 공개 자료를 다시 뒤져, 지방재정365의 다른 데이터(세출결산, 재정자립도 등)를 부르는 파이썬 클라이언트 [kpubdata](https://pypi.org/project/kpubdata/)(MIT)에서 실제 호출 형식을 확인했습니다. 어댑터에 넣어 두었던 주소(`lofin.mois.go.kr/HUB/BGTBOOK`)는 명세를 보고 추정한 값이었고, 실제 API는 새 사이트의 허브 한 곳으로 모여 있습니다.

```
GET https://www.lofin365.go.kr/lf/hub/<데이터코드>?Key=<인증키>&Type=json&pIndex=1&pSize=1000&<필터>
```

```json
{"<데이터코드>": [{"head": [{"list_total_count": 1234},
                             {"RESULT": {"CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다."}}]},
                   {"row": [{"fyr": "2025", "wa_laf_hg_nm": "서울특별시", "laf_hg_nm": "강남구", "…": "…"}]}]}
```

- 결과 코드: `INFO-000` 정상, `INFO-200` 해당 데이터 없음, `ERROR-290`·`ERROR-300` 인증키 오류, 그 밖의 `ERROR-*`는 요청 오류입니다. 실패한 호출은 `RESULT`를 최상위에 둡니다. 어댑터는 이제 이 코드를 읽어, 오류면 수집원을 멈추고(`FatalSourceError`) "데이터 없음"은 빈 해로 넘깁니다.
- 필드 이름은 허브 공통 규칙을 따릅니다. `fyr` 회계연도, `wa_laf_hg_nm` 광역자치단체명, `laf_hg_nm` 자치단체명입니다. 이 이름을 기본 후보 맨 앞에 넣었습니다. 예산서 링크 필드 이름은 아직 모릅니다.
- 한 번에 1,000건까지 받을 수 있어서 `pSize`를 1,000으로 올렸습니다.
- **데이터코드**는 데이터셋마다 다릅니다(예: 세출결산총괄 `AJGCF`, 재정자립도 `JFIED`). "우리 지자체 예산서"의 코드는 사이트에서 그 데이터의 OpenApi 탭을 열면 나옵니다. 코드는 `sources.config`의 `api_code`로 넣고, 없으면 첫 호출 전에 어떤 설정이 빠졌는지 알려 주며 멈춥니다.

```sql
UPDATE sources SET config = config || '{"api_code": "<예산서 데이터코드>", "institutions": ["서울특별시 강남구"]}'
WHERE key = 'lofin_budget';
```

다음 실행에 필요한 것은 두 가지로 줄었습니다. 예산서 데이터코드, 그리고 `www.lofin365.go.kr` 접속 허용입니다. kpubdata는 이 서버가 한때 TLS 1.2의 오래된 암호 조합만 받았다고 적어 두었습니다(최근 버전에서는 정상 인증서와 TLS 1.3으로 바뀌었다고 함). 연결이 TLS 단계에서 실패하면 인증서 검증은 그대로 두고 암호 조합만 맞추면 됩니다.

## 6. BUDLK 실호출 (2026-09-27)

§5까지로 남은 것은 데이터코드와 `www.lofin365.go.kr` 접속 허용 두 가지였습니다. 데이터코드는 포털의 "우리 지자체 예산서" 데이터 OpenApi 탭(`https://www.lofin365.go.kr/portal/LF5110000.do?pdtaId=1XOSAOBZ0PXQLICHDNEJ743790`)에서 `BUDLK`로 확인했습니다. 포털의 조회 조건은 기준년도, 지역명, 자치단체명입니다. 접속 허용은 환경 설정에 넣었다고 전달받아, 새 세션에서 그것부터 확인했습니다.

### 6.1 호출 기록

이 세션은 `data-go-kr` 환경에서 11:46 UTC에 새 컨테이너로 시작했습니다. 키는 환경 변수로만 넘기고, 본문은 파일로 받고, 상태 코드와 크기만 출력했습니다.

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `GET https://www.lofin365.go.kr/lf/hub/BUDLK?Type=json&pIndex=1&pSize=5&fyr=2025` + `Key` | 1 | `curl: (56) CONNECT tunnel failed, response 403`, 0.30 s, 본문 0 B |
| `GET https://www.lofin365.go.kr/` | 1 | `CONNECT tunnel failed, response 403` |
| `GET https://lofin365.go.kr/` | 1 | `Recv failure: Connection reset by peer` (TLS 단계) |
| `GET https://lofin.mois.go.kr/` | 1 | `Recv failure: Connection reset by peer` (TLS 단계) |

- 프록시 상태 화면에는 두 번 모두 `www.lofin365.go.kr:443`에 대해 "gateway answered 403 to CONNECT (policy denial or upstream failure)"가 남았습니다. 게이트웨이 메시지만으로는 정책 거부와 상위 연결 실패를 구분할 수 없습니다. 다만 첫 시도 때와 똑같이 **연결이 시작되기도 전에 0.3초 만에** 거절됐고, 허용 목록에 있는 `lofin365.go.kr`은 같은 시각에 TLS 단계까지는 갔습니다. 그래서 이번에도 정책 거부일 가능성이 높다고 봅니다.
- 터널이 열리기 전이라 키는 제공처에 전달되지 않았습니다. 키가 유효한지, 하루 한도가 얼마인지도 아직 모릅니다.
- 평문 HTTP 등 다른 경로로 같은 호스트를 확인해 보려던 요청은 이 세션의 자동 권한 검사가 막았습니다. 그것도 정책을 돌아가는 시도에 가깝다고 보고 더 하지 않았습니다. 다른 프록시, 미러, 캐시는 쓰지 않았습니다.
- `APP_ANTHROPIC_API_KEY`가 있는지 확인하는 명령도 권한 검사가 막았습니다. 예산서까지 가지 못해 어느 추출기가 돌지는 이번 실행과 상관이 없었습니다.

### 6.3 바꾼 것

- `sources/lofin.py`의 `DEFAULTS["api_code"]`를 `None`에서 `"BUDLK"`로 바꿨습니다. 이제 `sources.config`에 `api_code`를 넣지 않아도 `/lf/hub/BUDLK`를 부릅니다. 설정에 다른 코드를 넣으면 그 코드가 우선하고, 설정으로 코드를 비우면 전처럼 첫 호출 전에 멈춥니다.
- 테스트: `test_lofin_defaults_to_the_budget_book_dataset`(기본 경로와 덮어쓰기)를 더했고, 코드가 비었을 때 멈추는 확인은 `overrides={"api_code": None}`로 바꿨습니다.
- 필드명 후보(`DEFAULTS`의 `*_fields`)는 **바꾸지 않았습니다.** 예산서 링크·구분(본예산/추경)·등록일 필드의 실제 이름은 응답을 봐야 알 수 있고, 추측으로 순서를 바꾸면 틀린 확신만 더합니다. 같은 이유로 실제 행을 다듬은 픽스처 테스트도 넣지 않았습니다. 지금 테스트는 계속 명세 기준 계약 테스트입니다.
- 검증: `ruff check`, `ruff format --check`, `mypy` 통과, `pytest` 305개 통과. `manage eval all`은 main과 이 브랜치를 각각 새 DB(마이그레이션 → `seed` → `demo run`)에서 돌렸고, JSON의 값 143개가 모두 같았습니다. 이번 변경은 실제 수집원 기본값만 건드려 합성 세계 평가에는 영향이 없습니다. 이 컨테이너에는 Docker가 없어, 로컬 PostgreSQL 16에 pgvector 패키지를 설치하고 `redis-server`를 띄워 돌렸습니다.

### 6.4 남은 일

1. **`www.lofin365.go.kr` 허용 확인.** `data-go-kr` 환경의 네트워크 설정(허용 도메인)에 `www.lofin365.go.kr`이 저장돼 있는지 확인해 주세요. 저장돼 있는데도 403이면 게이트웨이 쪽 상위 연결 실패일 수 있으니, 그때는 국내 망에서 같은 URL이 열리는지 한 번 봐 주시면 원인을 가를 수 있습니다.
2. 열리면 순서대로 합니다. 목록 호출은 몇십 번이면 충분합니다.
   - `BUDLK`를 `pSize=5`로 한 번 불러 봉투·필드명을 적고, `DEFAULTS`의 필드 후보를 실제 이름으로 고칩니다. 실제 행 하나를 다듬어 픽스처로 넣습니다.
   - 2024~2026년 목록을 받아 건수·포괄률·본예산/추경·채움·링크 호스트·파일 형식을 잽니다.
   - 링크 호스트가 지자체 누리집으로 흩어져 있으면, 그 호스트 목록과 건수를 여기에 적고 허용 여부를 정합니다. 막힌 호스트는 돌아가지 않습니다.
   - 조달청 데이터가 있는 지자체(서울특별시 강남구, 경기도 성남시 등)로 `institutions`를 좁혀 10권 이내로 적재·처리하고 20건을 수기로 대조합니다.
3. 회의록(CLIK)은 키가 아직 승인되지 않아 이번에도 건드리지 않았습니다.
