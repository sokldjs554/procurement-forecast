# 지방재정365 예산서 첫 실호출 (2026-09-27)

조달청 소스는 30일치를 실제로 적재해 확인했습니다([`real-data-run.md`](real-data-run.md)). 이번에는 같은 방식으로 예산서 소스(`lofin_budget`, `sources/lofin.py`)를 실제 API에 붙여 봤습니다. 같은 날 세 번 시도했습니다. 앞의 두 번은 네트워크 정책에 막혀 API에 닿지 못했고(§1~§6), 허용 도메인에 `www.lofin365.go.kr`이 들어간 세 번째에 처음으로 응답을 받았습니다(§7). 받아 보니 이 API는 예산서 파일 목록이 아니라 **지자체마다 예산서 게시판 주소 하나를 알려 주는 목록**이었습니다. 그래서 목록은 끝까지 쟀지만, 예산서는 한 권도 처리하지 못했습니다. 게시판이 있는 지자체 누리집 243곳이 모두 컨테이너에서 막혀 있었기 때문입니다. 그 뒤 강남구·성남시 누리집이 허용되어, 게시판 크롤러로 성남시 예산서 6권을 받아 파이프라인을 끝까지 돌렸습니다(§8). 숫자는 모두 이 세션들에서 직접 본 것이고, 계산으로 낸 값은 따로 표시했습니다.

- 키: 이날 발급된 `APP_LOFIN_API_KEY`. 키는 환경 변수로만 넘겼고 출력·파일·커밋에 남기지 않았습니다. 받은 본문과 적재 로그에 키가 들어 있지 않은 것도 확인했습니다.
- 환경: 개발 컨테이너(`data-go-kr` 환경). 외부 요청은 컨테이너의 에이전트 프록시를 거칩니다.
- §7까지는 예산서까지 가지 못해 추출기가 한 번도 돌지 않았습니다. §8에서는 `APP_ANTHROPIC_API_KEY`가 이 환경에 없어 **규칙 기반 추출기**가 돌았습니다. LLM 비용은 모두 0입니다.

## 요약

**§8 (강남구·성남시 게시판)**

- **처음으로 실제 예산서를 처리했습니다.** 성남시 세출예산사업명세서 6권(2025·2026년 본예산과 제1·2회 추경, 77.92 MB(계산), 4,157쪽)을 받았습니다. 모두 PDF 텍스트층이고 OCR 쪽은 0입니다. 규칙 기반 추출기로 신호 2,329건(accepted 2,327, needs_review 2, rejected 0)이 나왔고, 본예산 한 권 처리에 약 3분 40초가 걸렸습니다.
- **20건 수기 대조**에서 사업명·금액·연도는 20건 모두 맞았습니다(원본 쪽을 다른 PDF 엔진으로 따로 읽어 확인). 틀린 것은 분야 분류(제 판단으로 11건)와, 조달로 이어지지 않는 이전경비·보조금 행까지 신호가 되는 점입니다.
- **강남구는 한 권도 받지 않았습니다.** 게시판은 첨부가 목록 행에 바로 붙은 모양인데, robots.txt가 첨부 경로(`/file/*`)를 막고 있습니다. 전에 쓰던 `urllib.robotparser`는 이 와일드카드를 읽지 못해, 고치기 전 크롤러였다면 막힌 파일을 받았을 것입니다.
- **성남시의 `BUDLK` 링크는 두 해 모두 404**였습니다. 누리집 메뉴에서 찾은 새 페이지는 게시판이 아니라 모든 해의 예산서가 한 페이지에 있고, 다운로드 주소가 JS에서만 만들어집니다. 서버는 TLS 1.2 `AES128-SHA`만 받아 파이썬 기본 설정으로는 연결되지 않았습니다(인증서 검증은 그대로 두고 암호 목록만 넓힘).
- **받은 그대로의 코드로는 신호가 0건**이었습니다. 실제 표에는 "세부사업:"이 없고 소계 행도 같은 모양입니다. 편성목이 뒤따르는 행만 세부사업으로 읽게 고쳤고, 줄바꿈된 산출기초, "기본경비", 추경으로 0이 된 사업, 잘린 부서 이름도 고쳤습니다. 연결 단계가 한 권의 비슷한 행들을 한 사업으로 묶던 것(사업명 최대 32개)도 막았습니다.
- **조달청 30일치와의 연결**: 예산 사업이 조달청 발주계획·입찰공고와 같은 기회로 묶인 것이 11개였고, 제 판단으로 맞음 1, 그럴듯함 4, 섞임 1, 틀림 5입니다. 맞은 것은 "수정로 271번길 통학로 정비 공사" 1억 원 → 같은 이름의 발주계획·입찰공고 8,397만 원입니다.
- `pytest` 321개 통과(307 → 321). `manage eval all`의 JSON은 main과 바이트까지 같습니다(값 148개. OCR 평가가 돌아 143개에서 늘었고, main도 같은 환경에서 148개).
- **전체 실행에 필요한 것**: 두 곳 모두 파일이 누리집과 같은 호스트라 따로 허용할 파일 서버는 없었습니다. 지자체마다 누리집 호스트 허용과 게시판 설정 한 벌이 필요합니다(§8.8).

**§7까지 (BUDLK 목록)**

- **API는 응답합니다(§7.1).** `GET www.lofin365.go.kr/lf/hub/BUDLK?Key=…&Type=json&pIndex=1&pSize=…&fyr=<연도>`가 `INFO-000`과 함께 행을 돌려줍니다. `fyr`가 연도 필터이고 필수입니다(빼면 `ERROR-300`). 틀린 키는 `ERROR-290`, 행이 없는 해는 `INFO-200`입니다.
- **한 행은 지자체 하나입니다(§7.2).** 2024·2025·2026년 모두 243행(시도 본청 17 + 시군구 226)이라 243개 지자체가 빠짐없이 들어 있습니다. 필드는 `fyr`, `wa_laf_hg_nm`, `laf_cd`, `laf_hg_nm`, `lnk_nm`, `lnk_url_nm` 여섯 개이고 채움은 모두 100%입니다. **본예산·추경 구분과 등록일 필드는 없습니다.**
- **링크는 파일이 아니라 게시판입니다(§7.3).** `lnk_url_nm`은 해마다 243개가 모두 서로 다른 호스트이고, 전부 지자체 자체 누리집입니다(lofin365 0개). PDF·HWP로 끝나는 링크는 0개입니다. 예산서 파일은 이 게시판을 따라 들어가야 나옵니다.
- **링크 호스트 243곳이 모두 막혀 있습니다(§7.4).** 2026년 목록의 호스트를 한 번씩 열어 보니 243곳 모두 프록시가 403으로 거절했습니다(`host_not_allowed`). 그래서 예산서 표본, 쪽수·OCR·청크·선별·신호 측정, 20건 수기 대조는 이번에도 하지 못했습니다.
- **버그 넷을 고쳤습니다(§7.5).** 필드명이 하나도 맞지 않아 실제 행 486개가 모두 `skipped:unmapped`로 버려지고 있었고, "서울강남구"처럼 붙은 이름이 `institutions`의 "서울특별시 강남구"와 맞지 않았고, 게시판 HTML을 PDF로 알고 내려받으려 했고, 빈 해의 `RESULT` 블록을 행 하나로 셌습니다.
- `pytest` 307개 통과(305 → 307). `manage eval all`의 JSON은 새 DB에서 main과 번갈아 돌려 바이트까지 같습니다(값 143개).
- **전체 실행에 필요한 것**: 예산서 파일을 받으려면 지자체 누리집 호스트를 허용해야 하고(최대 243곳, 표본만이면 몇 곳), 게시판마다 크롤러 설정을 넣어야 합니다(§7.6).

## 1. 호출 기록

모든 요청은 `curl`로 보냈고 상태 코드와 크기만 출력했습니다. 키를 붙인 요청은 첫 번째 줄뿐입니다.

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `GET https://lofin.mois.go.kr/HUB/BGTBOOK?Type=json&pIndex=1&pSize=5&fyr=2025` + `Key` | 3 | 3번 모두 `curl: (35) Recv failure: Connection reset by peer` |
| `GET https://lofin.mois.go.kr/` | 7 | 7번 모두 TLS 단계에서 끊김 |
| `GET http://lofin.mois.go.kr/` | 2 | 프록시의 `503`, 본문 "upstream connect error or disconnect/reset before headers … remote connection failure" |
| `GET https://lofin365.go.kr/` | 7 | `301 → https://www.lofin365.go.kr/` 2번, 끊김 5번 |
| `GET https://www.lofin365.go.kr/` | 2 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://www.data.go.kr/` | 1 | `CONNECT tunnel failed, response 403` (네트워크 정책) |
| `GET https://apis.data.go.kr/` | 1 | `400` (게이트웨이 응답, 연결은 정상) |

`lofin.mois.go.kr`은 HTTP로도 HTTPS로도 연결되지 않았습니다. `lofin365.go.kr`은 가끔 연결되지만 곧바로 막힌 `www`로 보냅니다. 두 호스트가 한 번씩이라도 응답한 것으로 보아 호스트 자체는 살아 있습니다. 끊김이 제공처 방화벽 때문인지 컨테이너 경로 문제인지는 여기서 구분할 수 없었습니다. 조달청 적재 때도 해외 경로에서 TLS가 가끔 끊겼지만, 그때는 12번 중 7번이 연결됐습니다.

### 확인하지 못한 것

과제로 받았던 측정 가운데 이번에 한 것은 없습니다.

| 항목 | 상태 |

## 2. 전체 실행에 필요한 것

1. **네트워크 허용**
   - `www.lofin365.go.kr`: 지금은 프록시가 막습니다. `lofin365.go.kr`이 여기로 보내므로 API가 옮겨 갔다면 거의 확실히 필요합니다.
   - `lofin.mois.go.kr`: 허용 목록에는 있지만 TLS 연결이 끊깁니다. 이 경로를 쓰려면 컨테이너 밖(국내 망)에서 한 번 연결되는지부터 확인해야 합니다.
   - `www.data.go.kr`: 데이터셋 15138708의 안내와 명세를 읽을 때만 필요합니다.
2. **파일 호스트**: 목록을 한 번도 받지 못해 **어느 호스트를 열어야 하는지 아직 모릅니다.** 목록 응답의 링크가 `www.lofin365.go.kr` 한 곳이면 1번으로 충분합니다. 지자체 누리집으로 흩어져 있으면 호스트마다 허용해야 합니다. 목록만 받아 보면 바로 알 수 있습니다. 파일 호스트가 막혀 있어도 목록 행 수와 필드는 잴 수 있고, 그때 파일 호스트 목록과 건수를 이 문서에 채우면 됩니다.
3. **이 세션의 권한**: 키를 붙인 후보 경로 호출과 키 없는 경로 탐색이 세션의 자동 권한 검사에 막혔습니다. 다음 실행에서 탐색까지 맡기려면 이 호출들을 허용해 주셔야 합니다.

네트워크가 열리면 순서는 이렇습니다.

```bash
cd apps/api
# 1) 목록만: 기관 목록을 비워 두지 말고, 몇 곳으로 좁혀서 파일 다운로드를 제한합니다
psql "$DB" -c "UPDATE sources SET config = config || '{\"institutions\": [\"서울특별시 강남구\"]}' WHERE key = 'lofin_budget'"
uv run manage sources ingest -s lofin_budget --days 365 --max-calls 30 --report budget.json
# 2) 적재된 예산서 처리
uv run manage pipeline run
```

`budget.json`의 `books`에 목록 행 수(`listed`), 거른 이유별 건수(`skipped:*`), 내려받은 권수(`downloaded`)가 나옵니다. 호스트나 경로가 다르면 코드 수정 없이 설정으로 바꿉니다.

```sql
UPDATE sources SET config = config || '{"base_url": "https://www.lofin365.go.kr",
  "overrides": {"list_path": "/새/경로", "url_fields": ["실제_필드명"]}}'
WHERE key = 'lofin_budget';
```

## 3. 고친 것: 내려받기 전에 거르기

예산서 한 권은 수십~수백 MB이고, 목록에는 지자체마다 본예산과 추경이 해마다 올라옵니다(243개 지자체 × 여러 권). 그런데 어댑터는 목록 행마다 곧바로 파일을 내려받았고, 수집 창(등록일) 확인은 **받은 뒤에** 했습니다. 창 밖의 권도 모두 내려받고 버리는 구조였습니다.

이제 행마다 이 순서로 판단하고, 통과한 행만 내려받습니다.

| 순서 | 거르는 조건 | 이유 |
|---|---|---|
| 1 | 기관명이나 파일 URL이 없음 (`skipped:unmapped`) | 매핑 실패. 필드명이 다르면 여기 쌓임 |
| 2 | 행의 회계연도가 요청한 연도 범위 밖 (`skipped:fiscal_year`) | 목록이 `fyr` 파라미터를 무시하는 경우에 대비 |
| 3 | 등록일이 수집 창 밖 (`skipped:window`) | 전에는 다운로드 뒤에 하던 확인 |
| 4 | `sources.config`의 `institutions`에 없는 기관 (`skipped:institution`) | 목록이 없으면 이 단계는 건너뜀 |

- 요청하는 연도 범위는 전과 같이 수집 창 첫해부터 마지막 해 + 1년입니다. 다음 해 본예산은 12월에 올라오기 때문입니다.
- `institutions`는 띄어쓰기를 무시하고 비교합니다. 행의 기관명만으로도, 지역명을 앞에 붙인 이름으로도 맞춥니다. 그래서 `"서울특별시 강남구"`는 지역명 "서울특별시", 기관명 "강남구"인 행과 맞고, 같은 목록에 부산광역시 중구가 있어도 `"서울특별시중구"`와 헷갈리지 않습니다.
- 지역명 필드(`region_fields`)는 새로 읽습니다. 실제 목록이 지역명·자치단체명을 따로 준다는 명세에 따른 것이고, 필드명은 다른 필드처럼 추정값입니다. 지역명은 문서의 `sido_hint`로 넘겨 "중구" 같은 동명 기관 해석에 씁니다.
- API 호스트(`base_url`)를 설정으로 바꿀 수 있게 했습니다. 전에는 `list_path`와 필드명만 바꿀 수 있었고 호스트는 코드에 고정돼 있었습니다.
- 코드: `sources/lofin.py`, `sources/registry.py`, `pipeline/backfill.py`(보고서에 `books` 추가). 테스트: `tests/unit/test_sources.py`의 `test_lofin_*` 두 개.

## 4. 남은 일

- 네트워크가 열리면 §1의 "확인하지 못한 것"을 모두 잽니다. 목록 호출은 몇십 번이면 충분합니다(연도 3개 × 페이지 수).
- 실제 응답 한 행을 받으면 이름·URL은 두고 개인정보만 뺀 픽스처로 계약 테스트를 바꿉니다.
- 같은 URL을 두 행이 가리키거나(본예산 파일이 추경 행에 다시 걸리는 경우 등) 파일이 바뀌지 않았으면 다시 받지 않도록 하는 것은, 실제 목록을 본 뒤 필요한지 판단합니다. 지금도 같은 파일은 저장소에서 한 번만 저장·처리됩니다.
- 회의록(CLIK)은 키가 아직 승인되지 않아 이번에 건드리지 않았습니다.

## 5. 실제 API 형식을 찾음 (같은 날 추가)

막힌 뒤 공개 자료를 다시 뒤져, 지방재정365의 다른 데이터(세출결산, 재정자립도 등)를 부르는 파이썬 클라이언트 [kpubdata](https://pypi.org/project/kpubdata/)(MIT)에서 실제 호출 형식을 확인했습니다. 어댑터에 넣어 두었던 주소(`lofin.mois.go.kr/HUB/BGTBOOK`)는 명세를 보고 추정한 값이었고, 실제 API는 새 사이트의 허브 한 곳으로 모여 있습니다.

```
GET https://www.lofin365.go.kr/lf/hub/<데이터코드>?Key=<인증키>&Type=json&pIndex=1&pSize=1000&<필터>
```

```json
{"<데이터코드>": [{"head": [{"list_total_count": 1234},
                             {"RESULT": {"CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다."}}]},
                   {"row": [{"fyr": "2025", "wa_laf_hg_nm": "서울특별시", "laf_hg_nm": "강남구", "…": "…"}]}]}
```

- 결과 코드: `INFO-000` 정상, `INFO-200` 해당 데이터 없음, `ERROR-290`·`ERROR-300` 인증키 오류, 그 밖의 `ERROR-*`는 요청 오류입니다. 실패한 호출은 `RESULT`를 최상위에 둡니다. 어댑터는 이제 이 코드를 읽어, 오류면 수집원을 멈추고(`FatalSourceError`) "데이터 없음"은 빈 해로 넘깁니다.
- 필드 이름은 허브 공통 규칙을 따릅니다. `fyr` 회계연도, `wa_laf_hg_nm` 광역자치단체명, `laf_hg_nm` 자치단체명입니다. 이 이름을 기본 후보 맨 앞에 넣었습니다. 예산서 링크 필드 이름은 아직 모릅니다.
- 한 번에 1,000건까지 받을 수 있어서 `pSize`를 1,000으로 올렸습니다.
- **데이터코드**는 데이터셋마다 다릅니다(예: 세출결산총괄 `AJGCF`, 재정자립도 `JFIED`). "우리 지자체 예산서"의 코드는 사이트에서 그 데이터의 OpenApi 탭을 열면 나옵니다. 코드는 `sources.config`의 `api_code`로 넣고, 없으면 첫 호출 전에 어떤 설정이 빠졌는지 알려 주며 멈춥니다.

```sql
UPDATE sources SET config = config || '{"api_code": "<예산서 데이터코드>", "institutions": ["서울특별시 강남구"]}'
WHERE key = 'lofin_budget';
```

다음 실행에 필요한 것은 두 가지로 줄었습니다. 예산서 데이터코드, 그리고 `www.lofin365.go.kr` 접속 허용입니다. kpubdata는 이 서버가 한때 TLS 1.2의 오래된 암호 조합만 받았다고 적어 두었습니다(최근 버전에서는 정상 인증서와 TLS 1.3으로 바뀌었다고 함). 연결이 TLS 단계에서 실패하면 인증서 검증은 그대로 두고 암호 조합만 맞추면 됩니다.

## 6. BUDLK 실호출 (2026-09-27)

§5까지로 남은 것은 데이터코드와 `www.lofin365.go.kr` 접속 허용 두 가지였습니다. 데이터코드는 포털의 "우리 지자체 예산서" 데이터 OpenApi 탭(`https://www.lofin365.go.kr/portal/LF5110000.do?pdtaId=1XOSAOBZ0PXQLICHDNEJ743790`)에서 `BUDLK`로 확인했습니다. 포털의 조회 조건은 기준년도, 지역명, 자치단체명입니다. 접속 허용은 환경 설정에 넣었다고 전달받아, 새 세션에서 그것부터 확인했습니다.

### 6.1 호출 기록

이 세션은 `data-go-kr` 환경에서 11:46 UTC에 새 컨테이너로 시작했습니다. 키는 환경 변수로만 넘기고, 본문은 파일로 받고, 상태 코드와 크기만 출력했습니다.

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `GET https://www.lofin365.go.kr/lf/hub/BUDLK?Type=json&pIndex=1&pSize=5&fyr=2025` + `Key` | 1 | `curl: (56) CONNECT tunnel failed, response 403`, 0.30 s, 본문 0 B |
| `GET https://www.lofin365.go.kr/` | 1 | `CONNECT tunnel failed, response 403` |
| `GET https://lofin365.go.kr/` | 1 | `Recv failure: Connection reset by peer` (TLS 단계) |

- `APP_ANTHROPIC_API_KEY`가 있는지 확인하는 명령도 권한 검사가 막았습니다. 예산서까지 가지 못해 어느 추출기가 돌지는 이번 실행과 상관이 없었습니다.

### 6.3 바꾼 것

- `sources/lofin.py`의 `DEFAULTS["api_code"]`를 `None`에서 `"BUDLK"`로 바꿨습니다. 이제 `sources.config`에 `api_code`를 넣지 않아도 `/lf/hub/BUDLK`를 부릅니다. 설정에 다른 코드를 넣으면 그 코드가 우선하고, 설정으로 코드를 비우면 전처럼 첫 호출 전에 멈춥니다.
- 테스트: `test_lofin_defaults_to_the_budget_book_dataset`(기본 경로와 덮어쓰기)를 더했고, 코드가 비었을 때 멈추는 확인은 `overrides={"api_code": None}`로 바꿨습니다.
- 필드명 후보(`DEFAULTS`의 `*_fields`)는 **바꾸지 않았습니다.** 예산서 링크·구분(본예산/추경)·등록일 필드의 실제 이름은 응답을 봐야 알 수 있고, 추측으로 순서를 바꾸면 틀린 확신만 더합니다. 같은 이유로 실제 행을 다듬은 픽스처 테스트도 넣지 않았습니다. 지금 테스트는 계속 명세 기준 계약 테스트입니다.
- 검증: `ruff check`, `ruff format --check`, `mypy` 통과, `pytest` 305개 통과. `manage eval all`은 main과 이 브랜치를 각각 새 DB(마이그레이션 → `seed` → `demo run`)에서 돌렸고, JSON의 값 143개가 모두 같았습니다. 이번 변경은 실제 수집원 기본값만 건드려 합성 세계 평가에는 영향이 없습니다. 이 컨테이너에는 Docker가 없어, 로컬 PostgreSQL 16에 pgvector 패키지를 설치하고 `redis-server`를 띄워 돌렸습니다.

## 7. BUDLK 응답을 처음 받음 (2026-09-27)

§6 뒤에 `data-go-kr` 환경의 허용 도메인에 `www.lofin365.go.kr`이 들어갔고, 새 세션에서 같은 호출을 다시 보냈습니다. 이번에는 첫 호출부터 응답이 왔습니다.

### 7.1 호출 기록과 응답 모양

키는 환경 변수로 넘기고, 본문은 파일로 받고, 상태 코드와 크기만 출력했습니다. 아래 표의 모든 요청에 `Key`가 붙어 있습니다(틀린 키 확인 한 줄만 빼고).

| 요청 (키 제외) | 시도 | 결과 |
|---|---:|---|
| `BUDLK?Type=json&pIndex=1&pSize=5&fyr=2025` | 1 | `200`, 1,212 B, 1.9 s, `INFO-000`, `list_total_count` 243, 행 5개 |
| `…&pSize=1000&fyr=2024` / `2025` / `2026` | 4 | `200`, 각각 47.5 KB·47.4 KB·47.5 KB, 행 243개씩. 2026년 첫 시도는 TLS 단계 끊김(`Connection reset by peer`), 다시 보내 받음 |
| `…&fyr=2019` | 2 | 첫 시도 끊김, 두 번째 `200`, 행 243개 |
| `…&fyr=2027` | 1 | `200`, `{"RESULT":[{"CODE":"INFO-200","MESSAGE":"해당하는 데이터가 없습니다."}]}` |
| `fyr` 없이 | 1 | `200`, `ERROR-300` "필수 값이 누락되어 있습니다." |
| 틀린 키(`Key=invalid`) | 1 | `200`, `ERROR-290` "인증키가 유효하지 않습니다." |
| `manage sources ingest` 두 번(고치기 전·후) | 6 | 모두 `200`. 한 번에 3회(2025·2026·2027), 2.1~2.2 s |

모두 16번 보냈고 14번 응답을 받았습니다. 끊긴 2번은 조달청 적재 때처럼 컨테이너 프록시와 상위 사이의 TLS 끊김이었고, 다시 보내면 받았습니다. 응답 시간은 1.8~2.2초였습니다.

정상 응답의 봉투는 §5에서 공개 클라이언트로 짐작한 그대로입니다.

```json
{"BUDLK": [{"head": [{"list_total_count": 243},
                     {"RESULT": {"CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다."}}]},
           {"row": [{"fyr": "2025", "wa_laf_hg_nm": "서울", "laf_cd": "1133000",
                     "laf_hg_nm": "서울강남구", "lnk_nm": "예산서",
                     "lnk_url_nm": "https://www.gangnam.go.kr/board/B_000742/list.do?mid=ID05_050302"}]}]}
```

- 빈 해와 오류는 `RESULT`를 **목록으로 감싸** 최상위에 둡니다. 어댑터의 결과 코드 판독은 이 모양을 이미 읽고 있었습니다.
- `ERROR-300`은 §5에서 "인증키 오류"로 적었지만 실제로는 필수 파라미터 누락이었습니다. 어느 쪽이든 수집원을 멈추는 것은 같아서 동작은 그대로 두고 주석만 고쳤습니다.
- 연도 필터 이름은 `fyr`가 맞습니다. 2019·2024·2025·2026년을 부르면 행의 `fyr`가 모두 부른 연도였습니다.

### 7.4 예산서 표본: 받지 못함

과제는 조달청 데이터가 있는 지자체(서울특별시 강남구, 경기도 성남시 등)로 10권 이내를 받아 처리하는 것이었습니다. 링크가 게시판이라 먼저 그 호스트에 닿는지부터 봤습니다.

- 강남구(`www.gangnam.go.kr`)와 성남시(`www.seongnam.go.kr`) 링크는 둘 다 프록시 CONNECT 403이었습니다.
- 2026년 목록의 243개 호스트를 루트 주소로 한 번씩 열어 봤습니다. **243곳 모두 막혔습니다.** HTTPS 238곳은 CONNECT 403, `http://` 링크 5곳(부산 동래구, 대구 북구, 경기 고양시, 경북 고령군, 경남 의령군)은 프록시가 `403`과 `x-deny-reason: host_not_allowed`로 답했습니다. 막힌 호스트를 돌아가는 다른 경로는 쓰지 않았습니다.
- 그래서 실제 경로는 목록 단계까지만 돌았습니다. `institutions`를 `["서울특별시 강남구", "경기도 성남시"]`로 두고 돌린 결과입니다.


### 7.5 고친 것

실제 응답으로 확인한 버그 넷입니다. 코드는 `sources/lofin.py`, 보고서는 `pipeline/backfill.py`입니다.

1. **필드명.** 추정해 두었던 링크 필드(`file_url` 등)가 실제 이름 `lnk_url_nm`과 달라 모든 행이 매핑 실패였습니다. `DEFAULTS`를 실제 이름으로 바꿨습니다. 기관 `laf_hg_nm`, 지역 `wa_laf_hg_nm`, 연도 `fyr`, 링크 `lnk_url_nm`, id `laf_cd`입니다. 구분(본예산/추경)과 등록일은 필드가 없어 후보를 비웠습니다. 문서 id는 `laf_cd`가 해마다 같아서 `"{laf_cd}-{fyr}"`로 만듭니다. 제목은 없는 구분을 지어내지 않고 "2026년도 강남구 예산서"로 씁니다.
2. **이름 풀기.** "서울" + "서울강남구"를 "서울특별시" + "강남구"로 풀고, "서울본청"은 "서울특별시"로 둡니다. 시도 약칭은 기관 사전의 `SIDO_ALIASES`를 씁니다. 이제 `institutions`의 "서울특별시 강남구"가 맞고, 문서의 `sido_hint`도 정식 명칭으로 넘어갑니다.
3. **게시판을 파일로 받지 않기.** 전에는 링크를 무조건 내려받아 MIME을 URL로 짐작했고, 짐작이 안 되면 PDF라고 적었습니다. 게시판 HTML이 PDF 예산서로 저장될 뻔했습니다. 이제 경로가 `.pdf`·`.hwp`·`.hwpx`로 끝날 때만 내려받고, 형식은 크롤러와 같은 방식(`sniff_mime`, 앞 바이트)으로 정합니다. 문서가 아니면 버리고 `skipped:not_a_document`로 셉니다. 게시판 링크는 내려받지 않고 `skipped:page_link`로 세며 `page_links`에 남기고, 보고서에 `page_link_hosts`(호스트별 건수)로 내보냅니다. 여러 지자체 누리집을 robots.txt 확인 없이 여는 일도 이렇게 막힙니다. 게시판은 그 규칙을 지키는 크롤러가 따라가야 합니다.
4. **빈 해의 `RESULT`.** 행을 찾는 함수가 최상위 `RESULT` 목록을 행 목록으로 읽어, 빈 해마다 가짜 행 하나를 셌습니다. `RESULT`는 이제 건너뜁니다.

테스트는 명세 기준 계약 픽스처를 **실제 행 하나**(2025년 강남구, 이름·URL 그대로)로 바꿨고, 다른 행도 같은 모양으로 만듭니다. 새로 더한 것은 실제 행 매핑(`test_lofin_maps_the_live_row`)과 파일 링크의 내용 확인(`test_lofin_a_file_link_must_hold_a_document`) 두 개입니다. 빈 해 테스트는 실제 `INFO-200` 모양으로 바꾸고 `listed`가 0인지 봅니다.

- 검증: `ruff check`, `ruff format --check`, `mypy` 통과, `pytest` 307개 통과. `manage eval all`은 main과 이 브랜치를 각각 새 DB(마이그레이션 → `seed` → `demo run`)에서 돌렸고 JSON이 바이트까지 같았습니다(값 143개). 이번 변경은 실제 수집원 어댑터만 건드려 합성 세계 평가에는 영향이 없습니다.

### 7.6 남은 일

1. **예산서 파일을 받는 길.** `BUDLK`는 "어디 가면 예산서가 있는지"만 알려 줍니다. 파일은 게시판 크롤러(`sources/crawler.py`)로 받아야 하고, 게시판마다 `detail_pattern`·`attachment_pattern` 같은 설정이 필요합니다. 169곳은 게시판 목록이 아니라 메뉴 페이지라 한 단계 더 들어가야 할 수도 있습니다. 보고서의 `page_link_hosts`와 어댑터의 `page_links`가 그 설정의 출발점입니다.
2. **네트워크 허용.** 표본 10권만 보려면 강남구·성남시처럼 고른 지자체의 호스트 몇 곳이면 됩니다. 전체를 돌리려면 §7.3의 호스트 243곳(2024~2026년을 합치면 248곳)이 필요합니다. 예산서 첨부가 게시판과 다른 파일 서버에 있으면 그 호스트도 필요한데, 이는 게시판을 열어 봐야 압니다.
3. **등록일이 없음.** 목록에 날짜가 없어 어댑터는 회계연도 전해 12월 20일을 등록일로 둡니다. 그래서 `--days 365`로 돌리면 올해 회계연도 행은 창 밖으로 빠집니다(이번 실행의 `skipped:window` 243). 게시판에서 실제 게시일을 읽게 되면 이 기본값은 크롤러 쪽 날짜로 바뀝니다.
4. 표본을 받으면 §6.4의 측정(크기·쪽수·OCR·청크·선별·신호·판정·시간, 20건 수기 대조)을 그대로 합니다.
5. 회의록(CLIK)은 키가 아직 승인되지 않아 이번에도 건드리지 않았습니다.

## 8. 게시판에서 예산서 받기: 강남구·성남시 (2026-09-27)

§7 뒤에 이 환경의 허용 도메인에 `www.gangnam.go.kr`과 `www.seongnam.go.kr`이 들어갔습니다. 그래서 `BUDLK`가 알려 준 두 지자체의 예산서 페이지를 직접 열어 보고, 게시판 크롤러(`sources/crawler.py`)로 예산서를 받아 파이프라인을 끝까지 돌렸습니다. 처음으로 실제 예산서가 들어왔습니다. 성남시에서 6권(4,157쪽)을 받았고, 강남구는 robots.txt가 첨부 파일 경로를 막고 있어 한 권도 받지 않았습니다.

- `APP_ANTHROPIC_API_KEY`가 이 환경에 없어서 추출은 **규칙 기반 추출기**(`llm/providers/heuristic.py`)가 했습니다. LLM 비용은 0입니다. 아래 신호 수와 판정은 모두 규칙 기반 추출기의 결과입니다.

- 두 사이트에는 요청을 적게 보냈습니다. 손으로 연 것은 강남구 3번, 성남시 curl 22번과 TLS 원인을 확인하려고 파이썬으로 연 3번입니다(모두 robots.txt를 먼저 읽고 허용된 경로만). 크롤러는 호스트마다 1.5초 간격을 뒀습니다. 게시판 호스트를 돌아가는 다른 경로는 쓰지 않았고, TLS 인증서 검증도 끄지 않았습니다.
- 이 컨테이너에는 Docker가 없어 PostgreSQL 16(pgvector)과 Redis를 직접 띄웠습니다. CI와 같게 `tesseract-ocr`·`tesseract-ocr-kor`·`fonts-nanum`도 설치했습니다.

### 8.1 두 페이지의 모양

**강남구** (`https://www.gangnam.go.kr/board/B_000742/list.do?mid=ID05_050302`)

- 메뉴 페이지가 아니라 **게시판 목록 그 자체**입니다. 한 쪽에 10행, 13쪽(글 122개)이고 열은 번호·제목·첨부·예산분류·작성일입니다. 예산분류(본예산·추가경정예산·기금운영·성인지예산·중기지방재정계획)는 비어 있는 행도 있습니다.
- **상세 페이지가 없습니다.** 제목 링크는 `href="javascript:;"`이고, 첨부 파일이 목록 행에 바로 붙어 있습니다(`/file/1/get/<UUID>/download.do`, 같은 호스트). 행마다 `preview.do`(미리보기) 링크도 있습니다. 파일 이름은 링크 글자가 아니라 아이콘 `img`의 `alt`에만 있습니다("2026년 강남구 예산서(최종).pdf 다운로드").
- 쪽 넘김은 `selectPage_func(n)`라는 JS이지만, 실제로는 GET 폼(`listForm`)의 `pgno` 파라미터라 `?pgno=2`로 열 수 있습니다.
- 첫 쪽에 있는 예산서는 셋입니다. "2026년도 강남구 예산서"(2026-01-13), "2025년 제2회 강남구 추가경정예산서"(2025-09-30), "2025년 제1회 강남구 추가경정예산서"(2025-07-11). 2025년 본예산서는 둘째 쪽 이후에 있을 텐데 열어 보지 않았습니다.
- **robots.txt가 첨부 경로를 막습니다.** `User-agent: *` 아래 `Disallow: /file/*`가 있어서, 목록의 파일은 전부 받을 수 없습니다. 그래서 강남구 예산서는 한 권도 내려받지 않았습니다. 게시판 목록(`/board/B_000742/`)은 허용입니다.

**성남시**

- `BUDLK`의 성남시 링크는 두 해 모두 **404**였습니다. 2025년 행은 `…/finance/financialDisclosure2025.do?menuIdx=1000524&returnURL=%2Fmain.do`, 2026년 행은 `…/city/1000170/339/11608/subTabCont.do?`입니다. 누리집이 개편되면서 주소가 바뀐 것으로 보입니다. 첫 화면(`/index`)의 메뉴를 따라가 "재정정보 › 예산정보 › 연도별 예산서"(`https://www.seongnam.go.kr/cn03050201`)를 찾았습니다.
- 게시판이 아니라 **한 페이지에 모든 해의 예산서가 있는 콘텐츠 페이지**입니다. 2020~2026년의 본예산·추경이 연도별 블록(`h4`)으로 나뉘고, 그 아래 회계(`h5`)·문서 종류(`h6`)와 목록(`li`)이 이어집니다. 2019년 이전 블록 13개는 제목만 있고 파일 링크가 없습니다. 게시일은 어디에도 없습니다.
- **다운로드 링크가 JS에만 있습니다.** `href="#download"`에 `onclick="fileDownload('/contents/down/budget/2026/','11608_3.pdf',…)"`이 붙어 있고, 호출이 529개(서로 다른 파일 487개)입니다. 실제 주소는 사이트 JS(`/humanframe/theme/portal/assets/script/common.js`)가 다시 만듭니다. `/humanframe/file/sncity/bgt/<연도>/<파일명>`이고, 연도는 블록 제목에서 가져옵니다. onclick에 적힌 경로(`/contents/down/budget/2026/11608_1.pdf`)는 404입니다. 파일은 같은 호스트에 있어서 **따로 허용할 파일 서버는 없습니다.** 2020~2026년 블록 14개 모두 onclick 경로의 연도와 블록 제목의 연도가 같았습니다.
- 2026년 3회·4회 추경 블록은 HTML 주석 안에 있습니다. 아직 올리지 않은 자리로 보이고, 크롤러도 주석은 읽지 않습니다.
- robots.txt는 `/api/`, `/comm/` 같은 경로만 막고 `/cn03050201`과 `/humanframe/file/`은 허용합니다.
- **TLS**: 이 서버는 TLS 1.2의 `AES128-SHA`(RSA 키 교환) 하나만 받습니다. 인증서는 Sectigo가 발급한 `*.seongnam.go.kr`로 정상입니다. curl은 OpenSSL 기본 암호 목록을 써서 연결되지만, 파이썬(3.11)의 기본 목록에는 이 암호가 없어 **httpx는 매번 `SSLV3_ALERT_HANDSHAKE_FAILURE`로 실패했습니다.** 처음에는 연결이 가끔 끊기는 사이트로 보였습니다. 실제로 curl도 22번 중 8번은 TLS 단계에서 끊겼고(`ws_closed_mid_exchange`), 이런 끊김은 다시 보내면 받았습니다. 하지만 파이썬 쪽 실패는 끊김이 아니라 암호가 맞지 않은 것이었습니다.
- 받은 6권의 `Last-Modified`는 모두 2026-06-18(KST)입니다. 게시일이 아니라 서버에 파일을 다시 올린 날로 보입니다.

### 8.2 크롤러에 넣은 것

게시판 하나에만 맞춘 코드는 넣지 않았습니다. 두 사이트에서 본 모양을 일반 규칙으로 만들고, 사이트별 차이는 설정으로 넣었습니다. 테스트는 두 사이트의 실제 HTML을 줄인 사본으로 만들었습니다(`tests/unit/test_crawler.py`).

1. **robots.txt를 RFC 9309대로 읽기.** 전에는 `urllib.robotparser`를 썼는데, 이 파서는 경로의 `*`를 글자 그대로 읽어 `Disallow: /file/*`가 아무것도 막지 못합니다. 또 `User-agent: *` 묶음이 여럿이면 첫 묶음만 씁니다. 강남구 robots.txt에 둘 다 있습니다(`Disallow: /board/B_000057/*`는 둘째 `*` 묶음에 있습니다). 고치기 전 크롤러였다면 **강남구가 막은 첨부 파일을 받았을 것입니다.** 이제 `*`·`$` 와일드카드, 같은 에이전트 묶음 합치기, 가장 긴 규칙 우선(같으면 Allow)을 따릅니다.
2. **목록 행에 붙은 첨부.** 상세 링크가 없는데 첨부 링크가 있는 행은 그 자체를 글 하나로 보고, 상세 페이지를 열지 않고 행의 파일을 받습니다(강남구).
3. **JS 링크(`script_links`).** onclick 속 호출을 정규식으로 읽어 URL 틀에 넣습니다(성남시).
4. **한 페이지 문서 목록(`"layout": "page"`).** 페이지의 첨부 하나가 문서 하나입니다. 제목은 위의 제목(`h1`~`h6`)과 목록 글자를 이은 것입니다("성남시 Seongnam City › 연도별 예산서 › 2026년 세입세출예산서 › 일반회계 › 세출예산사업명세서 › 전체"). 날짜가 없으니 제목의 회계연도로 수집 창을 정하고(창의 첫해 ~ 끝해+1), 파일의 `Last-Modified`를 게시일로 씁니다(`structured.published_from`).
5. **게시판별 설정, `title_pattern`, `max_files`.** 상세·첨부 패턴, 쪽 파라미터, 제목 조건을 게시판마다 덮어쓸 수 있습니다. `max_files`는 한 번에 받을 파일 수의 상한입니다(이번에는 6).
6. **`legacy_tls_hosts`.** 적힌 호스트에만 OpenSSL 기본 암호 목록을 씁니다. 인증서와 호스트 이름 검증은 기본과 똑같이 합니다(`sources/http.py`의 `legacy_cipher_context`, 테스트가 `CERT_REQUIRED`와 `check_hostname`을 확인).
7. **회로가 열린 호스트는 그 게시판만 건너뛰기.** 전에는 한 호스트의 회로 차단기가 열려 있으면 수집원 전체가 멈췄습니다. 성남시 연결 실패로 차단기가 열린 뒤의 실행은 수집원 전체가 `failed`로 끝났습니다. 이제 그 호스트의 게시판만 건너뛰고 다른 게시판은 계속 돕니다.
8. **제목 읽기.** "2025년 제2회 강남구 추가경정예산서"처럼 "년도"가 아닌 제목에서 회계연도를 못 읽었고, 제2회 추경을 그냥 "추가경정"으로 적었습니다. 이제 "년"·"회계연도"도 읽고 "제N회"를 그대로 적습니다.
9. 그 밖에 수집원 목록에 `budget_boards`(`adapter: crawler`, 기본 꺼짐)를 넣었고, 적재 보고서에 크롤러 통계(`crawl`)를 넣었습니다. 크롤러는 호스트마다 호출을 따로 세므로(`budget_boards@<호스트>`) 보고서의 `calls`도 이를 합칩니다. `manage sources ingest --days`의 상한은 366에서 731로 올렸습니다. 예산서는 1년에 한두 번 올라와서 400일 창이 필요했습니다.

한 가지 주의할 점도 테스트로 남겼습니다. 강남구 목록에서 기본값 `detail_pattern`(`view\.do`)은 미리보기 링크(`preview.do`)를 글로 잡습니다. 그래서 강남구 설정은 `B_000742/view\.do`로 좁혔습니다.

### 8.3 설정과 실행

설정은 저장소의 다른 수집원처럼 `sources.config`에 넣습니다. `manage seed`가 `budget_boards` 행을 만들고, 아래 SQL로 게시판을 넣고 켭니다.

```sql

     "page_param": "pgno", "title_keywords": [],
     "title_pattern": "강남구 (추가경정)?예산서$"},
```

성남시 설정은 일반회계 세출예산사업명세서만 고릅니다. 본예산은 "전체" 파일 하나, 추경은 그 추경의 세출예산사업명세서 하나입니다. 부서별로 나눈 파일(같은 내용)과 세입·특별회계는 뺐습니다.

```bash
uv run manage sources ingest -s budget_boards --days 400 --report boards.json
uv run manage pipeline run
```

적재는 다섯 번 돌렸습니다. 앞의 네 번은 성남시에서 한 권도 받지 못했습니다. 크롤러가 성남시 robots.txt부터 읽는데 이 요청이 매번 TLS 단계에서 실패해서, 규칙대로 그 실행 동안 성남시 전체를 건너뛰었습니다. 두 번째와 네 번째는 앞 실행의 실패로 열린 회로 차단기(600초) 때문에 거의 바로 끝났습니다. 차단기는 지우지 않고 기다렸습니다. 원인(§8.1의 TLS)을 고친 뒤 다섯 번째 실행 결과입니다.

### 8.5 예산 사업 20건 수기 대조

최종 코드의 신호 2,329건에서 20건을 무작위로 뽑았습니다(`md5(id || 'final20')` 순). 뽑은 행마다 원본 PDF의 해당 쪽을 PDFium(`pypdfium2`)으로 따로 읽어, 같은 쪽에 같은 사업명과 예산액이 한 줄에 있는지, 그 쪽이 `(단위:천원)`인지, 권의 회계연도와 신호의 연도가 같은지 확인했습니다. 파이프라인은 pypdf로 읽으므로 추출 엔진이 서로 다릅니다.

| 항목 | 맞음 | 틀림 |
|---|---:|---:|
| 사업명 | 20 | 0 |
| 금액 (예산액 × 1,000원) | 20 | 0 |
| 연도 | 20 | 0 |

- 맞은 예: "정자1동 복합청사 신축" 5,529,000천원 → 5,529,000,000원, 2025년(2025 본예산 33쪽). "가로수 및 녹지대 병해충 방제" 2,342,000천원, 2025년(1,302쪽). "성남시 청소년 교향악 페스티벌" 200,000천원, 2026년(361쪽).
- 금액 단위는 모든 쪽이 `(단위:천원)`이었고, 추출기의 기본 단위(천원)와 맞았습니다. 청크에는 단위 머리글이 들어가지 않아, 이번에는 기본값 덕분에 맞은 것입니다. 원 단위 예산서를 만나면 틀립니다.
- 추경 권의 금액은 추경 뒤 예산액입니다(예: "다문화사회 이해교육 17,150 24,500 △7,350" → 17,150천원). 기정액이 아닙니다.
- **세 항목 밖에서 본 오류**도 적습니다.
  - **분야 분류**: 20건 중 11건은 제 판단으로 분야가 맞지 않습니다(맞는 것 9건). "개별주택가격 조사·산정" → `facility`, "전국동시지방선거 추진" → `facility`, "성남시 청소년 교향악 페스티벌" → `education`, "지역사회 통합건강증진사업(구강보건)" → `education` 같은 것입니다. 규칙 기반 분류기는 청크 전체의 단어를 세는데, 예산 행 청크에는 산출기초 줄(○…)이 섞여 있어 엉뚱한 단어가 걸립니다.
  - **조달 대상이 아닌 행**: 20건 모두 실제 세부사업이지만, 조달로 이어질 만한 것은 "정자1동 복합청사 신축", "도로명 안내표지판 정비공사", "가로수 및 녹지대 병해충 방제" 정도입니다. "노인복지관 종사자 웰빙보조비", "청년 발달장애인 자산형성 사업" 같은 이전경비도 신호가 됩니다. 운영비 단어 목록만으로는 거를 수 없고, 편성목(401 시설비, 207 연구용역비 같은)을 보면 가를 수 있을 것 같습니다. 이번에는 고치지 않았습니다.
  - **같은 사업이 부서마다 한 줄**: "전국동시지방선거 추진 2,739천원"은 동 주민센터마다 한 줄씩 50쪽에 나옵니다. 행 자체는 맞지만 비슷한 신호가 50개 생깁니다.
- 고치기 전 추출기로도 20건을 따로 뽑아 대조했습니다(`md5(id || 'seed7')` 순). 세 항목은 20건 모두 맞았지만, 그중 1건이 "기본경비"였고 이것을 계기로 §8.6의 3을 찾았습니다.

### 8.6 예산서를 읽으며 고친 것

크롤러(§8.2) 밖에서, 실제 예산서가 보여 준 버그입니다. 테스트는 모두 성남시 예산서의 실제 줄을 줄여 만들었습니다(`tests/unit/test_parsing.py`, `tests/unit/test_llm.py`, `tests/integration/test_backfill.py`).

1. **표의 행을 읽지 못함 (신호 0건의 원인).** 합성 예산서는 "세부사업: 스마트쉘터 설치 352,000 0 352,000"처럼 줄 앞에 "세부사업:"이 붙지만, 실제 세출예산사업명세서에는 이 말이 없습니다. "상권활성화재단 출연 4,039,360 3,864,360 175,000"(예산액, 전년도 또는 기정액, 증감)뿐입니다. 게다가 부서·정책·단위사업의 소계 행도 똑같은 모양이고, 세부사업과 이름이 같기도 합니다("지역경제활성화"가 정책이자 세부사업). 둘을 가르는 것은 다음 줄입니다. 세부사업 행 다음에는 (국·도·시비 같은 재원 줄을 건너뛰면) 반드시 "306 출연금" 같은 세 자리 편성목이 옵니다. 그래서 청크 나누기는 편성목이 뒤따르는 행에서만 새 청크를 시작하고, 편성목·통계목·재원 줄은 그 청크에 붙입니다. 쪽마다 있는 머리글("…ㆍ세부사업ㆍ편성목 예산액 전년도")은 금액이 없으니 청크가 되지 않습니다. 추출기는 "세부사업:"이 없을 때 "이름 예산액 전년도 증감" 줄을 읽습니다. 청크는 52,303개에서 9,080개로 줄었습니다.
2. **줄바꿈된 산출기초의 꼬리.** "○자원안보위기 경보 에너지 민생안정 지원" 다음 줄 " 사업 전담인력 673,639 0 673,639"는 앞 줄이 넘어온 것인데, 행 모양이라 "사업 전담인력"이라는 사업이 됐습니다. 1차 수정 뒤 청크 146개(1.6%, 계산)가 이런 줄로 시작했고, "사업", "및 컨설팅", "리어 공사" 같은 잘린 제목이 나왔습니다. 금액이 없는 "○…" 줄 바로 다음 줄은 이제 행으로 보지 않습니다.
3. **"기본경비".** 부서마다 있는 행정운영경비 행입니다. 1차 수정 뒤 신호 2,619건 중 258건(9.9%, 계산)이 "기본경비"였습니다. 운영비 단어 목록에 넣었습니다.
4. **추경에서 0이 된 사업.** "미니태양광 보급지원사업 0 73,080 △73,080"은 추경으로 없어진 사업인데, 신호가 되어 예전 금액(73,080천원)을 달고 `budget_mismatch`로 검토 대기열에 갔습니다. 1차 수정 뒤 검토 28건 중 26건이 이것이었습니다. 예산액이 0인 행은 이제 신호를 만들지 않습니다.
5. **부서 이름이 잘림.** "부서: 분당구 건설과"를 "분당구"로 읽었습니다. 첫 낱말만 잡던 정규식을 줄 끝까지 읽게 했습니다. 구청 부서는 모두 이 모양입니다.
6. **한 권의 두 행이 한 사업으로 묶임.** 연결 단계는 같은 기관 안에서 제목·임베딩이 비슷하면 묶습니다. 합성 데이터에서는 문제가 없었지만, 실제 예산서에는 "…정비공사"처럼 비슷한 이름의 세부사업이 수십 개 있습니다. 고치기 전 연결에서는 예산 신호 2,327건이 기회 469개로 묶였고, 그중 169개(신호 1,542건)가 사업명을 둘 이상 담았습니다. 가장 큰 것은 사업명 32개였고, 신호 54건이 묶인 기회 하나는 도로과·공원과·녹지과·생태하천과·구청의 "정비공사"를 한데 모았습니다. 예산서는 세부사업을 한 번씩만 적으므로, 이제 예산 행은 **같은 권의 다른 행이 이미 들어 있는 기회**에는 붙지 않습니다(발주계획번호가 다른 계획끼리 묶지 않는 기존 규칙과 같은 방식). 다른 권(본예산과 추경, 다른 해)의 같은 사업끼리는 여전히 묶입니다.

`manage eval all`의 JSON은 main과 이 브랜치를 각각 새 DB(마이그레이션 → `seed --anchor 2026-09-27` → `demo run`)에서 돌려 **바이트까지 같았습니다**(값 148개). §7까지의 143개보다 5개 많은 것은 이번에 tesseract와 한글 글꼴을 설치해 OCR 평가(`ocr`)가 건너뛰지 않고 돌았기 때문입니다. main도 같은 환경에서 148개입니다. 합성 예산서의 행은 모두 "세부사업:"이 붙어 있고 한 권에 같은 사업이 두 번 나오지 않아, 이번 수정이 합성 평가에 닿지 않습니다. 그래도 추출·연결 코드를 바꿨으므로 크롤러만 바꿨을 때와 모든 수정을 마친 뒤, 두 번 비교했습니다. 설치 전에는 main에서도 OCR 평가가 가짜 PDF(글꼴이 없어 텍스트로 대신 저장된 것)에서 멈췄습니다. CI는 두 패키지를 설치하므로 CI와 같은 조건입니다.

### 8.8 전체 실행에 필요한 것

1. **호스트 허용.** 두 곳 모두 파일이 게시판과 같은 호스트에 있어서, 이번에 **따로 허용할 파일 서버는 없었습니다.** 프록시가 막은 요청(CONNECT 403)도 0번이었습니다. 다른 지자체로 넓히려면 §7.3의 누리집 호스트(해마다 243곳)를 필요한 만큼 허용해야 하고, 첨부가 다른 호스트에 있는 곳은 그 호스트도 필요합니다. 이는 게시판마다 열어 봐야 압니다.
2. **게시판마다 설정 한 벌.** 두 곳만 봐도 모양이 셋이었습니다. 목록형 게시판(첨부가 행에 붙음), 한 페이지 문서 목록(JS 링크), 그리고 `BUDLK` 링크가 죽어 사람이 메뉴를 따라가 찾아야 하는 경우입니다. 설정마다 게시판 주소, 상세·첨부 패턴(기본 `view\.do`는 미리보기 링크를 잡으니 좁혀야 함), 쪽 파라미터, 제목 조건, 필요하면 `script_links`와 `legacy_tls_hosts`가 들어갑니다. `BUDLK` 링크는 그 출발점일 뿐이고, 성남시처럼 틀릴 수 있습니다.
3. **robots.txt가 막은 곳은 받지 않습니다.** 강남구는 `Disallow: /file/*`로 첨부를 모두 막고 있어 이 크롤러로는 예산서를 받을 수 없습니다. 받으려면 먼저 강남구에 수집을 허용해 줄 수 있는지 물어야 합니다. 규칙을 돌아가지는 않습니다.
4. **날짜.** 한 페이지 목록에는 게시일이 없어 파일의 `Last-Modified`를 씁니다. 성남시 6권은 모두 2026-06-18이라, 실제 게시일(본예산은 전년 12월)과 다릅니다. 수집 창은 회계연도로 거르므로 수집에는 문제가 없지만, 신호의 관측일(`observed_at`)이 실제보다 늦습니다.
5. **추출.** 규칙 기반 추출기는 세 항목(사업명·금액·연도)은 맞혔지만, 분야 분류와 "조달로 이어질 행인가"는 약합니다(§8.5). LLM 추출기로 같은 6권을 돌려 비교하는 것이 다음 순서입니다. 청크 9,080개라 비용이 들므로, 먼저 `make eval-llm`의 `--dry-run`처럼 비용을 추정하고 사람이 한도를 정해 돌려야 합니다.
6. 본예산 한 권 처리에 약 3분 40초가 걸립니다. 243개 지자체의 본예산·추경을 해마다 받으면 워커 시간이 꽤 들어갑니다. 텍스트 추출 시간을 따로 재 보고, 쪽 단위로 나눠 처리할지 정해야 합니다.
