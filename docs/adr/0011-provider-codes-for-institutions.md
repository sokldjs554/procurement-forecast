# 0011. 조달청 문서의 기관은 조달청 코드로 식별한다

## 맥락
기관 해석은 이름에서 시도·시군구·의회·부서를 떼어 기관 사전과 맞추는 방식이었습니다. 회의록·예산서·누리집처럼 이름만 있는 문서원에 맞춘 설계입니다. 그런데 조달청 30일치(57,514건)를 넣어 보니 수요기관 이름이 6,344개였고, 대부분이 학교·대학·병원·공사·공단이었습니다. 번들 사전은 데모용 37곳이라 4.8%만 풀렸고, 나머지는 검토 대기열로 가서 연결되지 않았습니다([실데이터 30일 측정](../real-data-run.md)).

먼저 떠오르는 해법은 행정표준코드 기관 전체(수만 곳)를 사전에 넣는 것입니다. 하지만 조달청 레코드에는 수요기관코드가 이미 붙어 옵니다. 제공처가 정해 준 코드가 있는데 이름을 맞출 이유가 없습니다. 이름 맞추기는 추측이고, 사전이 커질수록 퍼지 매칭이 엉뚱한 기관에 붙을 여지도 커집니다.

## 결정
- **지자체는 전부 사전에 둡니다.** 시도 16곳, 시군구 227곳(+제주 행정시 2곳), 의회 243곳, 시도교육청 16곳입니다(2026-07-01 개편 뒤). 없어진 지자체의 행도 남겨 둡니다. 회의록·예산서가 말하는 기관이 여기 있고, 조달청 쪽 같은 지자체와 한 코드로 만나야 하기 때문입니다. 행정안전부 법정동코드 API의 스냅샷에서 `scripts/build_institutions.py`로 만듭니다.
- **나머지는 조달청 코드로 식별합니다.** 사전으로 풀리지 않는 조달청 레코드는 그 수요기관코드로 기관을 새로 만듭니다(`G2B-<코드>`). 다음 레코드부터는 이름을 보지 않고 코드로 찾습니다. 이름에서는 표시용 종류와 지역 필터용 시도만 읽습니다.
- **예외는 지자체처럼 생긴 이름입니다.** 사전에 없는 "○○시 ○○구"는 새 기관을 만들지 않고 검토 대기열로 보냅니다. 새 기관이 아니라 사전의 빈틈이라, 따로 만들면 같은 지자체가 둘이 됩니다.
- 코드로 만든 기관은 퍼지 매칭 대상에 넣지 않고, 사전에 있는 이름을 덮어쓰지도 않습니다.
- 사전이 바뀌면 `manage pipeline reresolve`로 저장된 문서의 기관을 다시 풉니다. 수요기관코드가 문서에 남아 있어서 다시 받을 필요가 없습니다.

## 결과
- 얻은 것: 조달청 레코드는 이름 모양과 상관없이 기관이 정해지고, 검토를 거치지 않고 연결 단계로 갑니다. 사전을 37곳에서 506곳으로 늘려도 합성 평가 지표는 하나도 바뀌지 않았습니다.
  - 같은 30일치를 새 DB에 넣고 다시 재 보니 연결 대상이 2,776건(4.8%)에서 54,665건(95.0%)으로 늘었습니다. 기회는 1,580건에서 26,415건, 번호 연결은 754건에서 18,099건이 됐습니다. 코드로 만든 기관은 5,336곳입니다([측정 §8](../real-data-run.md#8-기관-사전-전체와-조달청-코드)).
  - 입찰공고 → 발주계획 번호 쌍은 15,232쌍 모두 같은 기회에 들어갔습니다. 표본으로 본 사전 쪽 문서 40건은 주인이 모두 맞았습니다.
- 치른 비용:
  - **사전규격에는 수요기관코드가 없습니다**(9,286건 중 0건). 사전규격은 발주계획·입찰공고가 등록해 둔 이름과 글자 그대로 같을 때만 기관을 찾습니다. 그래서 적재 순서를 탑니다. 새 DB에서는 사전규격이 입찰공고보다 먼저 들어와 558건을 놓쳤고, `reresolve`로 되찾았습니다. 한 번도 코드와 함께 나오지 않은 이름(한국수자원공사 272건 등, 654건)은 풀 방법이 없습니다. 레지스트리가 프로세스마다 CSV로 시작하므로, 이름이 메모리에 없으면 DB의 코드 기관을 이름으로 찾아봅니다.
  - **사전 원본보다 새로운 지자체 개편은 사전을 다시 만들 때까지 검토 대기로 갑니다.** 2026년 조달청 데이터에는 "전남광주통합특별시 …"(1,965건)와 인천의 영종구·서해구·제물포구·검단구(95건)가 먼저 나왔고, 한동안 남은 미해석 2,859건의 72%였습니다. 지자체 모양이라 결정대로 새 기관을 만들지 않았습니다. 법정동코드 API로 사전을 다시 만든 뒤(2026-09-27) 같은 30일에서 2건만 남았습니다([측정 §9](../real-data-run.md#9-2026-행정구역-개편-반영)). 개편마다 사람이 코드를 읽고 판단할 몫도 남습니다. 이름만 바뀐 정부는 기관 코드를 그대로 두고 옛 이름을 별칭으로 두지만, 합치거나 나뉜 곳은 새 기관으로 넣고 옛 행을 남깁니다. 인천 서구는 서해구·검단구 둘 다 새 코드를 받아 나뉜 것으로 봤습니다. 옛 코드의 폐지일은 API의 폐지 코드 조회가 막혀 확인하지 못했습니다. 이름이 지자체 모양이 아닌 산하기관과 새 교육청의 청사는 여전히 코드 기관이 돼서, 사전의 `EO-12000`과 따로 셉니다.
  - 이름에서 읽는 종류·시도는 거칩니다. 대법원·국회 같은 헌법기관과 그 소속기관 26곳은 `central`이 아니라 `public_agency`입니다. "전남"을 전라남도로 읽어 "전남광주통합특별시 …" 코드 기관 44곳이 전라남도가 되던 것은 새 시도 이름을 넣으며 고쳤습니다. 다만 이미 저장된 코드 기관의 시도는 `reresolve`가 고치지 않아서, 지역 필터가 광주·전남과 전남광주를 같은 시도로 봅니다. 표시와 지역 필터에만 영향이 있습니다.
  - 코드로 만든 기관의 상하 관계(학교 → 교육지원청 → 교육청)는 모릅니다. "서울특별시 강남구 보건소"처럼 이름에 지자체가 드러나는 산하기관은 이름 해석이 지자체로 올려 주지만, 그렇지 않으면 따로 남습니다.

## 다시 볼 조건
교육청 단위 집계처럼 상위 기관 기준으로 봐야 하는 기능이 생기면, 행정표준코드의 상위기관코드를 들여와 코드로 만든 기관에 부모를 붙입니다.
