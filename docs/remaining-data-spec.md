# 남은 데이터 한계 보완 명세

2026-09-29. 사용자가 공개 데모는 직접 맡고, 남은 코드·데이터 보완을 완료한 뒤 보고하라고 지시했다. 이 변경은 공개 데모 호스팅과 유료 자원 생성을 포함하지 않는다.

## 완료할 동작

1. **사업과 여러 계약**: 서로 다른 공고를 강제로 합치지 않고, 기존 기회 사이에 검토된 `project_contract` 관계를 저장한다. 방향은 사업 근거(회의록/예산)가 있는 기회에서 조달 근거가 있는 기회로 한다. 원문 근거, 판정자, 시간, 판정 이력을 보존한다. 동일 기관·유효 신호·서로 다른 기회를 검사하고 거절/재판정은 멱등하게 처리한다. 관계는 기존 계약 금액을 사업 예산에 합산하거나 예측을 자동 상승시키지 않는다. 관리자 API와 검토 UI, 기회 상세의 관계 표시를 제공한다. 혼합된 과거 기회는 자동 분해하지 않고 감사 목록으로 노출한다.
2. **예산 분류**: 편성목과 이웃 행의 일반 단어가 사업명보다 강하게 작용하는 문제를 재현해 수정한다. 용도를 먼저 보고 기술 단어만으로 오분류하지 않는다. 근거가 약하거나 충돌하면 `other`/검토 대상으로 표현한다. 과거 문서에 기록된 판정은 회귀 사례로만 사용하며 독립적인 새 정확도로 주장하지 않는다.
3. **수집 품질**: 기관별 설정·실제 수집·원문 보존 여부를 구분하는 커버리지 보고서를 제공한다. 전국 243곳을 설정 개수만으로 수집 완료라 주장하지 않는다. CLIK의 새로운 수정 DOCID를 다음 수집에서 인식하고 기존 검토 보호 정책을 거친다. robots와 호스트 허용 목록을 우회하지 않는다.
4. **사람 검토 → 평가자료**: 판정된 신호와 실제 근거/원문 해시를 고정한 평가자료 내보내기를 제공한다. 문서 단위 분할과 데이터 digest를 기록하고, 원문이 없거나 grounding이 불충분한 자료는 정답으로 자동 승격하지 않는다. 유료 LLM 호출은 없다.
5. **순서와 시점 검증**: 보존된 실신호를 공개일순/예산우선/역순으로 재연결해 차이를 계량한다. 완전한 역사적 원문이 없는 입력은 `historical as-of` 평가로 표시하지 않는다. 실제 연결 정답과 재현성은 다른 지표로 보고한다.
6. **앞으로의 시점 고정**: 현재 관측 시점의 원문·근거·벡터·연결·예측·모델 식별 정보를 기관 범위의 일관된 스냅샷으로 내보낸다. 현재 저장 상태를 과거 상태인 것처럼 소급하지 않는다. 원문/벡터 누락은 불완전 사유로 기록하고, 제한 초과는 부분 파일을 완전한 스냅샷으로 저장하지 않는다. 이후 관측 결과와 비교할 출발점을 보존한다.

## 불변 조건

- 기존 신호·검토·추천 피드백·알림 기록을 삭제하지 않는다. 자동 이행은 원문/판정 손실을 일으키지 않는다.
- 합성 추출·연결 P/R ≥ 0.95를 낮추지 않는다. `truth_id`를 파이프라인에서 읽지 않는다.
- 쿼리 변경은 운영 규모 벤치와 실행 계획으로 확인한다. 파이프라인 변경은 `manage eval all` 전후 비교한다.
- 유료 LLM 호출/외부 통지/공개 데모 배포를 하지 않는다.
- 실데이터 정확도 향상은 분리된 실제 정답 평가가 있을 때만 주장한다. 새 원문, 장기 관측, 전국 기관별 접근권한, 법률 판단은 코드만으로 생성하지 않는다.

## 설계 결정

기존 `OpportunitySignal`의 소속 구조를 전면 교체하는 대신 관계 테이블을 추가한다. 기존 ID와 사용자의 북마크/피드백을 보존하면서 사업 하나와 독립적인 여러 계약을 표현할 수 있다. 과거 혼합 기회를 자동으로 쪼개는 작업은 정답 없이 안전하게 결정할 수 없으므로 감사 결과에 남기고 검토된 관계부터 축적한다.
