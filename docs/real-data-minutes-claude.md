> [`real-data-minutes.md`](real-data-minutes.md)(규칙 기반 추출기로 잰 34건)의 후속입니다.

앞선 시도에서는 Claude 수치를 내지 못했습니다. 첫 번째는 키가 없었고, 두 번째는 API가 크레딧 잔액 부족으로 20번 모두 거절했습니다(비용 $0).

## 1. 환경과 코드

- 브랜치는 `docs/minutes-claude`이고, 측정 코드는 main `34cdd39`에 §8의 파서 수정(`9227835`)을 더한 것입니다.
- **API 호출은 파서 수정 전에 했습니다.** 파서는 응답을 받은 뒤 검증 단계에서만 쓰입니다. 그래서 아래 검증기 결과는 캐시된 같은 응답을 수정 후 코드로 다시 검증한 값이고, 수정 전 값은 §8에 따로 적었습니다.
- 새 컨테이너에 PostgreSQL 16 + `postgresql-16-pgvector`, Redis, `tesseract-ocr`·`tesseract-ocr-kor`·`fonts-nanum`을 설치했습니다(Docker 없음). 순서는 `manage db upgrade` → `manage seed --anchor 2026-09-25`입니다.
- Claude 호출에는 `APP_LLM_PROVIDER=anthropic`, `APP_LLM_DAILY_BUDGET_USD=24.9`를 주었습니다.
- 키는 설정 여부만 확인했고, 출력·파일·커밋에 남기지 않았습니다. `api.anthropic.com`에는 프록시를 거쳐 닿았습니다.

## 4. 나란히 비교할 20개 청크

[`real-data-minutes.md` §6](real-data-minutes.md#6-회의록-신호-20건-수기-대조)의 표본은 신호 39건을 `md5(id || 'minutes20')` 순으로 뽑은 20건입니다. 그 신호들이 나온 청크는 다음과 같습니다.

1152, 8439, 1055, 1854, 2018, 1554, 7607, 6251, 1732, 1813, 1814, 4669, 6063, 1877, 2079, 2746, 6970, 8692, 2143, 1866

이번 DB에서도 20개 모두 같은 번호, 같은 글자 범위로 있고 모두 선별을 통과합니다. 청크별 규칙 기반 신호도 앞 시도의 표와 같습니다. 그러니 두 추출기는 같은 청크 분할에서 비교됩니다.

**Claude에 보낸 방법(제 결정)**
- 규칙 기반으로 처리한 복사본에서 `pipeline/process.py`와 같은 `ChunkContext`를 만들었습니다.
- 적재 직후 DB의 다른 복사본(`app_c20`)을 세션으로 삼아 `runtime.llm.extract`(파이프라인이 부르는 그 함수)에 보냈습니다. 동시 호출은 5개였습니다.
- 호출 기록(`llm_calls`)과 응답 캐시(`llm_cache`)는 `app_c20`에 쌓입니다. 캐시 키는 모델·effort·프롬프트·스키마·사용자 메시지로 만들어지므로, 같은 청크를 다시 보내도 과금되지 않습니다.
- 응답은 파이프라인의 `_text_signal`(→ `domain/grounding.py`의 `verify_extraction`)로 검증했습니다. 검증을 건너뛴 값은 없습니다.
- 34건 전체에 파이프라인을 다시 돌리지 않은 이유: 문서 단위로 돌리면 20개 청크가 든 문서의 다른 청크까지 모두 Claude로 가기 때문입니다.

**증상.** 청크 1152의 "예산액은 한 2억 4000 정도로"를 Claude는 240,000,000으로 냈습니다. 검증기는 이를 `budget_mismatch`로 보고, 파서가 읽은 200,000,000으로 바꿔 저장했습니다(ADR-0006의 "숫자는 파서가 최종 판정한다").

**원인.** `domain/krw.py`의 금액 정규식이 억·조 뒤의 단위 없는 숫자를 "원"이 뒤따를 때만 금액에 넣었습니다. 그래서 "2억 4000"에서 "4000"이 빠졌습니다. "2억 4천"은 이미 2억 4천만으로 읽고 있었으니(#10), 같은 구어 규칙의 빈틈입니다.

**수정.**
- 억·조 바로 뒤의 1~4자리 숫자는 한 단계 아래 단위로 셉니다(억 → 만, 조 → 억).
- 뒤에 "년·월·일·개·명·건·호·차·회·층·곳·%"가 오거나 소수이면 넣지 않습니다.
- "원"으로 끝나는 쓴 금액("2억 4000원" → 200,004,000)은 전과 같이 글자 그대로 읽습니다.
- "2억 2027 착공"처럼 "년" 없이 연도가 붙은 경우는 "2억 2000"(2억 2천만)과 구별할 수 없어 금액으로 읽힙니다. 알려진 한계로 남깁니다.

테스트는 `tests/unit/test_krw.py`에 넣었고, 이 회의록의 문장 그대로입니다.
