# 새 회의록 검증 세트: 처음 보는 문서에서 추출이 맞는가

목표는 하나입니다. 개발에 쓰지 않은 실제 회의록에서도 사업명·금액·시점·확약 수준을 맞게 뽑는지 재고, 고친 뒤에도 처음 보는 문서로 다시 확인합니다. 이전 검증 세트(`docs/data/holdout-2026-09-30` 등)는 이미 여러 번 보고 고친 자료라 여기서는 쓰지 않습니다.

## 1. 문서 고르기 (읽기 전에 고정)

- 출처: 국회도서관 지방의정포털(CLIK) Open API의 회의록 목록과 본문.
- 기간: 2026-08-16~2026-09-25에 열린 회의.
- 회의 종류: 이름에 "위원회"가 들어간 회의. 상임위원회와 예산결산특별위원회입니다.
- 제외: 이 저장소의 평가나 개발에서 실제 문서를 쓴 기관, 그리고 개발용 손글씨 발췌문에 이름이 나온 기관 전부([목록](data/fresh-minutes-exclude.txt), 54곳).
- 순서: 회의 ID의 SHA-256 오름차순. 의회마다 1건씩 앞에서부터 10건.
- 실행: [`fresh-minutes.yml`](../.github/workflows/fresh-minutes.yml)(`manage eval fresh-minutes`). 원문과 해시는 `data/fresh-minutes` 브랜치에 남깁니다.

## 2. 개발용과 시험용 나누기

- 위 순서의 **앞 5건은 개발용**입니다. 오류를 보고 추출기를 고치는 데 씁니다.
- **뒤 5건은 시험용**입니다. 정답을 먼저 고정하고, 개선을 마칠 때까지 추출 결과를 보지 않습니다. 개선 전 기준선과 개선 후 결과를 마지막에 한 번씩만 잽니다.

## 3. 발췌문과 정답

- 발췌문은 규칙으로 고릅니다(`select_excerpts`).
  - 금액이나 구매류 행위(구매·설치·용역·구축·도입·교체·공사·발주·입찰·계약·임차)가 나오는 발언만 대상입니다.
  - 길이는 80~2,500자입니다.
  - (문서, 위치) 해시 순서로 문서당 6개를 뽑습니다.
  - 그래서 수당·보조금처럼 조달이 아닌 발언도 들어가고, 그런 발언이 음성 사례가 됩니다.
- 정답은 이 저장소 작업을 맡은 AI(Claude Code)가 원문을 읽고 씁니다. **독립 전문가 정답이 아닙니다.** 개발용과 시험용 모두 추출기를 한 번도 돌리기 전에 고정하고 SHA-256을 기록합니다.
  - 발췌문에 있는 조달 사업을 빠짐없이 적습니다. 사업명 핵심어, 금액(원), 예상 연도, 확약 수준(committed·planned·discussed)을 적습니다.
  - 보조금·인건비·수당·출연금·이미 끝난 사업은 조달 신호가 아닙니다.
  - 판단이 갈리는 경우는 이유와 함께 별도로 표시하고 점수에서 따로 셉니다.
- 형식은 기존 `source-holdout-v1`이라 `manage eval holdout`으로 바로 잴 수 있습니다.

## 4. 잴 것

- 규칙 기반 추출기(무료)와 Claude 추출기(운영 설정 그대로)를 잽니다. Claude 실행은 사용자가 승인한 상한 **$5** 안에서만 합니다(`--max-usd`).
- 지표: 사업명 일치(정밀도·재현율), 금액 일치, 연도 일치, 확약 수준 일치, 음성 발췌문 오탐. 개발용과 시험용 결과를 따로 보고합니다.
- 결과는 좋든 나쁘든 그대로 남깁니다. 정답은 고정 뒤 고치지 않습니다. 정답 오류를 발견하면 원래 정답으로 잰 점수와 함께 별도 파일로 남깁니다.
